## 1. 目标

在不改变 Faryo 运行架构和安全边界的前提下，把 Owner 会话页完善为受
DeepSeek Harness 启发的现代 Agent 工作台：桌面端具有清晰、安静的对话主轴，
移动端能够单手切换会话、查看状态、阅读 Markdown/TeX、观察实时执行并可靠地
向现有 tmux/Codex 或 Claude TUI 提交内容。

最终结果必须同时满足：

1. 对话阅读体验明显改善，但仍然是 Faryo 自己的视觉身份。
2. 360--430 px 手机宽度不是桌面布局的压缩版，而是独立设计的单栏工作流。
3. 已经解决的认证、实时同步、输入确认、公式渲染和滚动问题不得回归。
4. 不修改 tmux 窗口尺寸、Codex/Claude TUI 宽度或终端自动换行行为。
5. 公开仓库中不出现真实 Token、Cookie、邮箱、域名、会话内容或本机私有路径。

## 2. 参考与许可证边界

设计参考固定到 DeepSeek Harness 的已审查提交
[`47f943859bef60e4160492346772ded9b24f765a`](https://github.com/deepseek-ai/deepseek-harness/tree/47f943859bef60e4160492346772ded9b24f765a)。
该项目采用 MIT License，可以在保留许可证声明的条件下复用代码；本阶段优先
借鉴信息架构、间距、视觉层次和交互原则，不直接移植其 React/Vite/Cordis
应用外壳。

边界如下：

- 不复制 DeepSeek 名称、鱼形标志、品牌文案或制造官方关联印象。
- 若后续复制可识别的源代码片段，单独记录来源、固定提交和许可证，并补充
  `NOTICE`；纯粹重新实现设计原则不混入对方运行时代码。
- 不持续追踪 Harness `master`。参考版本固定，避免 developer preview 的破坏性
  变更进入 Faryo。
- Faryo 继续使用无构建步骤的 HTML/CSS/JavaScript 和本地静态资源；是否引入新的
  Markdown 解析依赖必须在渲染阶段单独决策。

## 3. 必须冻结的现有行为

以下能力是新版 UI 的回归基线，不因视觉重构而改变：

| 能力 | 冻结要求 |
| --- | --- |
| Owner/Gateway 认证 | 所有读取和写请求继续携带正确认证；不得将凭据写入 DOM、日志或仓库 |
| 网页输入 | `/api/send` 成功必须代表已确认提交；失败保留草稿；客户端消息 ID 保持幂等 |
| 实时显示 | 结构化最终消息继续由 Codex App Server 提供；执行中允许显示脱敏 tmux live 尾部 |
| 滚动 | 主对话位于底部时跟随更新；用户上翻后不得被新内容强制拉回 |
| Live tmux | 内层滚动位于底部时跟随；用户上翻后保持相对阅读位置 |
| Markdown/TeX | 本地离线加载；禁用原始 HTML；危险协议、路径越界和 XSS 继续被拒绝 |
| 手机输入 | 保留 `visualViewport`、安全区、草稿恢复和输入框失焦后尺寸稳定 |
| tmux/TUI | `FARYO_OWNER_PANE_WIDTH=0` 的语义保持不变，不执行 `resize-window` |
| Gateway | CSRF、严格 Cookie、登录限速、CSP 和 Cloudflare Access 外层边界不弱化 |

## 4. 目标信息架构

### 4.1 桌面与宽屏平板（宽度不小于 960 px）

采用三层但非强制三列的工作台：

```text
会话导航（可折叠） | 居中对话主轴 | 按需打开的详情面板
                    | 固定浮动输入器 |
```

- 会话导航用于切换活动会话和返回 Gateway，不承担文件管理器职责。
- 对话主轴的理想阅读宽度为 720--780 px，宽屏不再把消息扩展到整个视口。
- 详情面板默认关闭，用于 Raw、执行状态、附件和会话元信息。
- 工具/过程/Live tmux 是可折叠的执行证据，不与最终回答争夺视觉层级。
- 输入器保持居中、稳定、可扩展，发送、附件和中断状态始终可辨认。

### 4.2 手机（宽度小于 720 px）

手机采用真正的单栏布局：

```text
轻量顶栏
对话正文
回到最新按钮
稳定的大输入器

会话列表 -> 左侧全高抽屉
详情/Raw -> 全屏面板或底部面板
```

- 不保留占据正文宽度的折叠侧栏。
- 顶栏只展示会话标题、运行状态和菜单入口。
- 正文左右留白 10--12 px；用户消息不超过可用宽度的约 88%。
- 输入器在 focus、blur 和软键盘开关后保持相同的基础高度；只随真实文本行数增长。
- 表格、显示公式和代码块在自身容器内横向滚动，不撑宽整个页面。
- Live tmux 默认折叠并显示“正在执行”摘要；用户主动展开后尊重内层滚动位置。
- 所有主要触控目标至少 44 px，并适配顶部、底部安全区。

### 4.3 中间宽度（720--959 px）

- 保持单个对话主轴。
- 会话导航使用覆盖式抽屉，不挤压中心内容。
- 详情使用覆盖式侧面板；关闭后中心内容恢复原宽度。

## 5. 技术路线

### 5.1 保留的架构

- Python Owner/Gateway 服务和现有 API 路径不变。
- 结构化会话读取、SSE 刷新、tmux 输入与 Raw 路径不变。
- 继续使用渐进增强的原生 HTML/CSS/JavaScript，不引入 Node 生产运行时。
- 继续使用仓库内 KaTeX、markdown-it 和字体资源，直到渲染阶段的替换方案通过
  等价测试。

### 5.2 前端隔离策略

- 在页面根节点加入明确的新版 UI 标识，新增设计令牌只在 Owner 会话页生效。
- 先新增布局容器和语义化控制，不删除旧 ID；现有 JavaScript 查询和 API 行为因此
  保持兼容。
- CSS 按“令牌 -> 外壳 -> 组件 -> 响应式 -> 可访问性”组织，避免继续扩大单行规则。
- 新交互状态由小型纯函数管理并增加 Node 测试；不把布局状态混入认证/发送状态机。
- 每个阶段形成独立提交，阶段验收失败时回退单个提交，而不是回退整个功能分支。

## 6. 分阶段执行

### 阶段 A：基线、设计令牌和对话主轴（P0）

范围：`index.html`、`style.css`、前端静态测试、本文档。

工作项：

- 固化当前截图和关键 DOM/尺寸基线。
- 引入 Faryo 自有的中性色、蓝色操作色、圆角、阴影、间距和层级令牌。
- 建立全视口工作台背景和 748 px 左右的居中阅读主轴。
- 重新设计顶栏、消息层次、过程行、计划卡、错误提示和回到最新按钮。
- 将输入器改为稳定的大型浮动面板，保持现有控件 ID 和提交逻辑。
- 补充 `prefers-reduced-motion`、`:focus-visible` 和高对比度边界。

验收：

- 现有 Node/Python 测试全部通过。
- 390x844、412x915、768x1024、1440x900 下无横向页面滚动。
- 空输入、1 行、5 行、最大高度以及 focus/blur 后输入器几何符合预期。
- 当前认证、发送、SSE、Raw/Chat 切换和 tmux 宽度行为完全不变。

### 阶段 B：响应式导航和详情面板（P0）

范围：Owner `index.html`、`app.js`、`style.css`，必要时增加独立布局模块和测试。

工作项：

- 将现有会话弹出菜单升级为可访问的覆盖式会话抽屉。
- 新增桌面折叠导航入口，但不复制 DeepSeek 品牌或图标。
- 将 Raw、会话信息和附件状态组织到按需详情面板。
- 手机端面板全屏/底部显示；桌面端以覆盖层或可选侧栏显示。
- 实现焦点圈定、Escape 关闭、背景滚动锁定和返回焦点。
- 切换会话前持久化当前草稿，并保持现有选中会话 URL 语义。

验收：

- 键盘、触屏和屏幕阅读器均能打开、浏览和关闭面板。
- 360 px 下会话抽屉不挤压正文，44 px 触控目标无重叠。
- 切换会话不丢草稿、不重复订阅、不泄露上一会话内容。

### 阶段 C：执行过程和 Live tmux（P1）

范围：compact rules、`app.js`、`live-scroll.js`、样式与测试。

工作项：

- 将 process、plan、状态和 Live tmux 表现为可折叠执行卡。
- Agent 运行时展示轻量状态摘要；最终结构化回复到达后自动收敛。
- 保存用户对 Live tmux 的展开状态，但不同会话之间不共享内容状态。
- 展开状态变化不触发主对话强制滚动；已有内层滚动算法继续工作。

验收：

- 高频 live 更新不会把用户从历史阅读位置拉回顶部或底部。
- 展开/折叠时主对话累计布局偏移可接受。
- Raw 始终能提供原始终端证据，Compact 不伪装成完整终端。

### 阶段 D：成熟 Markdown/TeX 管线（P0）

范围：`markdown-render.js`、`math-render.js`、本地依赖、渲染测试和许可证文件。

工作项：

- 建立明确的 `streaming` 与 `settled` 两种渲染模式。
- `streaming` 对未闭合 Markdown、代码围栏和数学定界符采取保守显示，不闪现错误公式。
- `settled` 完整解析 GFM、表格、链接、图片、代码块和 TeX。
- 为 LaTeX 环境、`\[...\]`、`\(...\)`、`$$...$$`、`$...$` 以及终端受损输入建立
  不互相冲突的优先级。
- 覆盖分段函数、矩阵、范数、指示函数、对齐环境、长公式、表格内公式以及公式后的
  中文标点。
- 比较继续增强 markdown-it 与引入 micromark/mdast 子集的体积、安全性和维护成本；
  只有新方案显著减少启发式修复且能完全离线时才替换。

验收：

- 用户已报告的复杂控制理论样例全部形成匿名化回归夹具并正确渲染。
- 代码块中的美元符号和 TeX 字符串不被误渲染。
- 宽公式只滚动自身；正文不变窄、不逐字竖排、不截断后半部分。
- XSS、危险链接、图片来源和本地文件边界测试全部通过。

### 阶段 E：实时性和可靠提交联合回归（P0）

范围：只在测试发现回归时修改 `app.js`、Owner 服务或同步代码。

工作项：

- 测量 TUI、结构化历史、Owner、SSE 和 DOM 的更新时间。
- 验证页面可见、后台、锁屏恢复、断网重连和会话切换。
- 连续提交短文本、中文、多行、公式和附件引用；验证一次点击只产生一个 turn。
- 验证发送失败、TUI 已有草稿、请求超时和晚到响应。

验收：

- 正常本机条件下新内容无需手动刷新，最终结构化内容在既定 2 秒目标内出现。
- 发送成功时 TUI 已接受 turn；失败时网页草稿仍在。
- 同一客户端消息 ID 重试不产生重复 turn。

### 阶段 F：Gateway 视觉统一（P1）

Owner 会话页稳定后，才将同一组 Faryo 设计令牌应用到 Gateway 的 Active
Sessions、Session History 和 Projects。Gateway 的服务端分页、活动会话发现、远程关闭
权限和安全策略不随视觉重构改变。

验收：

- 活动会话和历史会话仍是两个明确区域。
- 历史保持每页 10 条、页码跳转和 Previous/Next。
- 手机端能够在两次触控内从首页进入任一活动会话。

### 阶段 G：完整发布验证（P0）

- Node 前端单元测试。
- 选择项目 Conda 环境后的 Owner/Gateway Python 测试。
- Owner 和 Gateway HTTP smoke。
- Chromium 桌面与设备视口浏览器测试；具备条件时补 Edge。
- 本地直连、Gateway 代理和公网 Access 后路径的非敏感回归。
- 离线资源、CSP、CSRF、认证、日志脱敏和 Git secrets/隐私扫描。
- 确认 `git diff` 不包含生成缓存、截图中的真实对话或运行时配置。

## 9. 完成定义

只有同时满足以下条件才标记本目标完成：

- 桌面和手机目标布局完成，且用户认可实际观感。
- Markdown/TeX 已覆盖已知失败类型，没有竖排、截断或错误合并为一行。
- 实时更新无需频繁手动刷新，网页提交一次就被同一 tmux TUI 接受。
- Live tmux 不抢夺用户滚动位置。
- 全量测试、浏览器验证、安全与隐私检查通过。
- 功能分支推送到个人 `origin`，稳定备份仍可访问，原作者 `upstream` 未被修改。
