# Faryo v1.6.0 Structured Interactions and Owner UI Plan

计划索引：[`README.md`](README.md)

更新时间：2026-08-21

状态：实施中

目标分支：`main`

## 1. 背景与问题基线

Faryo 已经把最终对话正文从 Codex rollout JSONL 增量读取，并在必要时使用 Codex
App Server 作为结构化兼容后备；Raw 与 Live tmux 则保留终端证据。这个读取方向适合
Markdown、TeX、历史分页和实时回答，但活动控制仍主要依赖向真实 tmux/Codex TUI
粘贴文字和发送按键。

普通 prompt 可以通过新增 rollout 用户事件、明确的 queued follow-up 或保守的输入框
消失证据确认。Codex 临时进入菜单或启动问答时，普通发送协议不再成立。当前已确认的
问题包括：

1. 精确输入 `/model` 时，文本消失可能只代表打开补全或模型菜单，却可能被普通发送
   路径误认为一个对话回合已提交；网页没有可靠的模型与 reasoning effort 选择界面。
2. 恢复历史线程时，如果记录目录已经移动、删除或与当前启动目录不同，Codex 会显示
   `Choose working directory to resume this session`。Owner 只检测到 Codex 进程就宣布
   ready，页面随后停在 `session unknown`、终端 fallback 或 `Waiting for output...`。
3. Owner 仅用少量终端尾部正则决定是否显示 Previous/Next/Enter，目录选择、工作区信任
   及未来新增菜单容易遗漏；刷新或切换会话也没有可重放的 pending-interaction 身份。
4. 移动端 composer 只根据 `visualViewport.height` 推断键盘开关，没有用 viewport offset
   修正 fixed footer，因此 Edge/Android 在不同键盘与滚动状态下可能过高或过低。
5. Owner 的主要交互仍集中在大型原生 `app.js` 与 `style.css` 中。输入、命令提示、状态、
   面板、会话切换和异步刷新共享命令式 DOM，新增一种交互时难以保证状态穷尽和旧响应
   隔离。
6. `/usage` 等命令不是普通 prompt：部分命令打开只读信息面板，部分进入编号菜单，部分
   启动新的 Codex 回合。仅为 `/model` 增加特例会把相同缺陷留给其余 slash 命令。
7. Goal pill 只能显示 Active/Done 等摘要，不能按需查看当前目标内容和详细状态；同时目标
   内容属于对话隐私，不能为了显示方便进入主页索引、诊断、日志或 localStorage。
8. 新建/恢复会话的目录浏览器固定过滤点目录。始终显示会造成噪声，始终隐藏又无法选择
   `.venv`、`.config` 等合法目录，需要用户控制且默认关闭的切换。
9. 部分活动会话的页头长期显示 `git --`。这不是视觉占位问题：必须校验 thread、tmux
   pane cwd、managed session 记录的 Git root 和实际 worktree 的映射及刷新时序。
10. Codex TUI 的 `Cwd [All] / Status Active` 能显示部分最近恢复过的顶层历史，但 Faryo
    Session History 和搜索遗漏。现场证据表明这些记录是 `source=cli|vscode`、rollout
    `parent_thread_id=None`，但 SQLite 的 `thread_source` 为 `NULL`；Faryo 只接受精确
    `thread_source='user'`，错误排除了合法 legacy/migrated 顶层线程。

这些问题有同一个根因：结构化对话数据面已经存在，但活动交互控制面没有一等状态；
单独添加更多前端正则或仅更换 UI 框架都不能解决根因。

## 2. 目标

### 2.1 产品目标

1. 为每个活动会话提供可恢复、可失效、可测试的结构化 pending interaction。
2. `/model` 和模型按钮共用同一模型选择流程；选择真实作用于 tmux 中的 Codex TUI，
   不作为聊天消息进入历史。
3. 恢复历史线程在启动前完成目录预检；存在歧义时先由 Faryo 显示现代目录选择界面，
   Codex 自身目录菜单只作为版本兼容后备。
4. 启动状态区分 `starting`、`pending_interaction` 与真正可输入的 `waiting`，不再以“进程
   存在”替代“会话 ready”。
5. 刷新、SSE 重连与会话切换后能够重建当前 pending interaction；旧标签页或旧菜单的
   迟到操作不得作用于新状态。
6. 修正 Android/Edge 软键盘下 composer 的 VisualViewport 偏移，同时保持 focus/blur
   基础几何一致。
7. 把 Owner 的动态交互壳增量迁移到 Preact + TypeScript + Vite，删除已经被替代的旧
   实现，不长期维护两套同功能代码。
8. 对当前 Codex slash inventory 建立行为分类：普通 prompt、立即动作、信息面板、编号
   菜单和启动工作流；所有本地 TUI 命令使用同一安全执行入口，优先完整支持 `/model`
   和 `/usage`。
9. Goal pill 可点击显示当前 goal 的 objective、状态、耗时和可用预算字段；内容只从当前
   已认证会话按需读取，关闭面板即释放，不写浏览器持久存储。
10. 目录选择器提供“显示隐藏文件夹”切换，默认关闭并可按设备记忆；切换不削弱后端路径
    policy。修复活动会话 `git --`，让页头使用当前线程/worktree 的真实状态。
11. Session History、搜索、计数、分页、恢复和 archive 对齐 Codex TUI：接受经过 source
    与 rollout 顶层证据约束的 `thread_source IS NULL` legacy/migrated 线程，继续排除真正
    的 subagent/guardian/memory 线程。

### 2.2 工程目标

- 专用检测器只做纯解析；真实按键、会话锁、身份和重试由统一服务拥有。
- 浏览器不解析 ANSI/tmux 文本，不决定方向键次数，也不直接构造未经校验的本机路径。
- TypeScript 判别联合覆盖所有前端交互状态，未知 kind 必须进入明确 fallback。
- 依赖固定版本、本地构建并提交浏览器产物；生产运行不要求 Node、CDN 或宽松 CSP。
- 公开仓库中的夹具只使用匿名标题、匿名目录和合成终端文本。

## 3. 非目标

- 不把 Faryo 改写成 DeepSeek Harness，也不引入 Cordis、动态插件加载器或其品牌资源。
- 不在本阶段把真实 Codex TUI 替换为纯 App Server/headless runtime；桌面 tmux 同步仍是
  产品能力。
- 不假设独立 App Server 可以直接修改另一个活动 Codex CLI 进程的模型状态。
- 不重写已经稳定的 Markdown/TeX AST、完整历史分页、Raw/Chat、复制和 Live tmux
  渲染核心；它们先作为明确的渲染岛接入新外壳。
- 不改变 Cloudflare Access、Owner token、Gateway CSRF、Cookie 或允许身份策略。
- 不修改 tmux 窗口、pane 或 Codex TUI 几何。

## 4. 参考原则

DeepSeek Harness 的可借鉴点是结构化会话和交互，而不是视觉复制：

- `/model` 命令和 composer 模型入口共用一个 per-session ModelDirectory；
- 历史与实时事件进入同一会话对象，重连通过 generation fence 重建；
- Web 入口保持很薄，业务状态位于可测试的对象层；
- pending approval/question 带稳定身份，展示层不从终端文字反推业务含义。

Faryo 与 Harness 的差异是：Faryo 控制一个外部 Codex CLI/TUI。因此需要一个明确的
`CodexTuiAdapter`，并为结构化 App Server 能力保留独立适配器。采用的是状态边界和
重连原则，不复制其大型 monorepo/plugin 拓扑。

参考：

- <https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-model-selection/README.md>
- <https://github.com/deepseek-ai/deepseek-harness/blob/master/.agents/notes/implemented/architecture/2026-07-19-gui-web-client-architecture.md>
- <https://github.com/deepseek-ai/deepseek-harness/blob/master/.agents/notes/implemented/architecture/2026-07-19-gui-layering-and-rpc-protocol.md>

## 5. 冻结的安全与可靠性边界

| 边界 | v1.6.0 要求 |
| --- | --- |
| 发送幂等 | 普通 prompt 继续使用不可变 session + client message id；504 不得重复粘贴正文 |
| 会话隔离 | 每个 interaction 绑定 session、generation 与指纹；旧响应返回 409，不发按键 |
| TUI 草稿 | 发现桌面未发送草稿时不覆盖；交互开始前确认 composer 状态 |
| 认证 | 所有 interaction GET/POST 与 SSE 继续走 Owner token、Gateway route 与 CSRF 边界 |
| 路径 | 恢复目录必须存在、解析 symlink 后仍在允许 roots，并使用不透明 selection token |
| 隐私 | API/日志/审计不记录 prompt、回答、完整 capture、Token、Cookie 或未脱敏路径 |
| 审计 | 只记录动作类型、匿名目标、结果、耗时和幂等信息；不记录 option label/路径正文 |
| tmux | 不执行 resize-window/resize-pane；真实客户端宽度与换行不改变 |
| systemd | Owner unit 必须使用 `KillMode=process`；restart/update 只停止 Web bridge，不能向同 cgroup 的 tmux/Codex 发信号 |
| 渲染 | Markdown/TeX、Raw/Chat、历史导航、复制和 Live tmux 不因外壳迁移改变语义 |

## 6. 目标架构

### 6.1 状态流

```text
Codex rollout/App Server ────────────────> structured transcript island

Codex TUI capture ─> CodexTuiAdapter ─┐
resume preflight ─> ResumeAdapter ─────┼─> InteractionService
structured capability adapter ─────────┘          │
                                                   ├─> versioned snapshot/SSE
                                                   └─> idempotent respond POST
                                                              │
                                                              v
                                                Preact InteractionHost
                                                ├─ ModelSelectSheet
                                                ├─ ResumeDirectorySheet
                                                ├─ ApprovalSheet
                                                └─ GenericTuiFallback
```

### 6.2 后端数据契约

公开 payload 使用固定字段，不返回原始 ANSI capture：

```json
{
  "id": "ix_<opaque>",
  "generation": 7,
  "kind": "model_select",
  "title": "Select model",
  "prompt": "Choose the model used by the next turn.",
  "options": [
    {
      "id": "opt_<opaque>",
      "label": "Model A",
      "description": "",
      "selected": true,
      "disabled": false
    }
  ],
  "actions": ["previous", "next", "choose", "cancel"],
  "source": "codex-tui",
  "status": "pending"
}
```

约束：

- `id` 由 session 的服务端匿名身份、kind、capture 指纹和 generation 生成；不把 tmux/
  thread id 原样编码进客户端 ID。
- `option.id` 是当前 interaction 内的不透明 ID，客户端不提交行号、路径或任意按键。
- `generation` 在状态改变、会话切换、进程重启和检测源改变时单调更新。
- 服务端重新 capture 并确认指纹后才响应动作；状态已变化返回 409。
- pending interaction 默认只驻留内存；刷新通过当前真实状态重新检测，不把终端正文写盘。

### 6.3 适配器与纯函数

新模块建议拆分为：

```text
apps/owner/local-tmux-owner/
  interaction_types.py
  codex_tui_interactions.py
  interaction_service.py
  resume_service.py
```

纯检测器：

```text
detect_model_selector(capture)
detect_resume_directory_selector(capture)
detect_workspace_trust_selector(capture)
detect_approval_selector(capture)
```

检测器不得调用 tmux、HTTP、文件系统或全局缓存。统一 registry 按具体到通用的顺序运行；
未知但明显阻塞的 TUI 菜单进入 `generic_tui`，保留明确的 Previous/Next/Choose/Cancel 后备，
不能假装是普通 composer。

副作用由 `InteractionService` 提供：

```text
current(session)
begin(session, kind, client_request_id)
respond(session, interaction_id, action_or_option, client_response_id)
```

### 6.4 `/model` 流程

1. 前端命令 registry 只在输入等于精确 `/model` 时转入结构化命令；`/model ...` 未知参数
   不被静默改写。
2. 模型按钮与 `/model` 调用同一个 begin endpoint。
3. 服务端获取该 session 锁，确认真实 Codex TUI 和无冲突桌面草稿。
4. 在 TUI 中打开真实 `/model` 菜单，等待 `detect_model_selector` 返回稳定快照。
5. 浏览器显示模型/effort；option 选择通过当前真实高亮与最短导航计划转换为按键。
6. 服务端等待菜单关闭或进入下一层 effort 菜单，再返回新 interaction/ready 状态。
7. `/model` 不使用普通 `/api/send`，不要求 rollout 新用户消息，不清除失败草稿。

若当前 Codex 版本只能可靠提供 Previous/Next/Choose，则第一阶段仍返回结构化 kind 和
通用 actions；只有经过真实夹具验证后才声称支持按名称直接选择。

### 6.5 全部 slash 命令的行为分类

不能把所有 `/command` 都当作 prompt，也不能假设所有命令都会打开菜单。当前 46 项
只代表 Codex 0.148.0 的已验证快照，不是永久协议常量。采用版本化 `CommandCatalog`：

- fallback snapshot 保存 `schemaVersion`、`testedCodexVersion`、命令、描述与少量已知行为
  override；Python、浏览器与测试从同一生成源读取，不各自硬编码一份清单；
- 安装、升级和 `faryo doctor` 使用隔离、固定几何的只读 slash popup inventory 探针，生成
  私有 runtime catalog 并与 fallback 比较；探针不提交命令，不改变现有 tmux geometry；
- Codex 版本或 inventory 漂移时，已知命令继续工作，新增命令显示为 `Unclassified`，删除
  命令不再展示，doctor 给出明确 warning 而不是让 Owner 启动失败；
- 未分类命令只能经一次性、显式确认的通用 executor 运行；不自动重试 Enter，不使用普通
  rollout prompt 确认，也不记录参数或终端正文；
- 删除、退出、登出、清空和停止等危险 override 独立于描述文字，并始终需要二次确认。

runtime catalog 随 Codex 二进制版本/签名失效，存放在私有 Owner cache；公开仓库只保留
匿名 fallback 和生成工具。行为分类如下：

| 类型 | 示例行为 | Faryo 收据 |
| --- | --- | --- |
| `prompt` | 成为模型可见输入/启动回合 | 继续要求 rollout/queue 证据 |
| `local_action` | 立即切换设置或执行本地动作后回到 composer | 要求终端状态指纹变化 |
| `panel` | `/usage` 类只读面板 | 返回结构化 panel interaction，允许 close/scroll |
| `menu` | `/model`、权限或 personality 类编号选择 | 返回 options/actions interaction |
| `workflow` | resume/fork/review 等多阶段启动问答 | 返回当前阶段 interaction，逐阶段确认 |

精确 slash 命令先进入 `CommandInteractionService`。服务端通过当前 CommandCatalog、
当前 composer、发送后 capture delta、detector registry 和 rollout evidence 判定结果；未知
或 Codex 版本漂移时不得重复 Enter，也不得伪称已提交。命令提示、快捷按钮和未来命令面板
共用同一 registry。测试脚本继续从真实 TUI 读取 inventory，并补充行为分类 drift 报告。

### 6.6 历史恢复目录流程

1. `prepare_resume` 读取线程 metadata，但不立即创建 tmux。
2. 记录 cwd 存在且在 route/root scope 内时直接使用。
3. cwd 丢失、越界或需要用户决定时返回 Faryo 自有 `resume_directory` interaction。
4. 前端复用安全目录浏览器，选项由后端 selection token 表示；用户选择后再启动 Codex。
5. managed tmux 写入 thread id、选定 cwd 与 starting marker；只有正常 composer 或已识别的
   pending interaction 才结束启动等待。
6. 若 Codex 自身仍显示 resume cwd 菜单，专用 TUI 检测器接管；不得卡在 unknown/loading。

目录浏览 API 增加显式 `showHidden`，默认 `false`。前端工具栏提供可访问的切换按钮并按
设备记忆，但后端每次仍重新验证 route roots、resolved symlink、可读目录和 selection token；
隐藏属性只影响展示，不成为权限判断。

### 6.7 Goal 详情与 Git 状态

Goal 摘要继续随常规 status/SSE 返回，但 objective 与详细字段只通过按需、no-store 的
authenticated endpoint 获取。解析器从当前 thread 的 create/get/update goal 事件重建最近
状态，clear 后返回 `none`；不把 objective 放入 diagnostics、Gateway Session History、审计、
DOM dataset 或 localStorage。Goal pill 支持键盘和触控打开详情 sheet，显示加载/空/错误/活动/
完成状态，迟到响应按 session generation 丢弃。

Git 状态采用一个明确的 current-worktree resolver：优先使用活动 thread 的真实 cwd 和
managed session 启动时记录的 resolved Git root，并与当前 pane cwd 交叉校验；仓库移动、
resume 目录选择和 session switch 后强制失效旧缓存。不存在 Git worktree 时显示 `No Git`
而不是含义不明的永久 `git --`，暂时加载则显示 `Git loading`。

### 6.8 Codex 历史兼容谓词

所有历史入口共用一个顶层线程 SQL predicate，不再在列表、恢复、归档与搜索中复制略有
差异的字符串。对 `source IN ('cli','vscode')`，`thread_source='user'` 与 legacy/migrated
`thread_source IS NULL` 都可见；`thread_source='subagent'` 及 JSON subagent/guardian source
继续排除。NULL 兼容必须同时满足顶层 source，并由匿名 rollout fixture 验证
`parent_thread_id=None`，不能泛化为“所有 NULL 都是用户对话”。

部署回归以合成标题查询比较 Codex DB 与 Owner/Gateway 结果数量；真实标题和正文不进入
公开测试、计划、日志或截图。

### 6.9 API 与实时同步

计划新增的版本化能力：

```text
GET  /api/interaction?session=...
POST /api/interaction/start
POST /api/interaction/respond
GET  /api/goal?session=...
```

现有 `/api/events` snapshot 增加可选 `interaction` 与 `interactionRevision`。旧客户端忽略
新增字段；新客户端首次加载、SSE 重连和 session switch 都以服务端 snapshot 为真。

POST 约束：

- start/respond 都需要不可变 client request id；重复请求返回同一收据。
- 只有 pending interaction 接受 respond；已 resolved/stale 返回明确状态。
- 网络失败不能自动重复发送方向键，除非收据或当前交互状态证明前一动作未生效。

### 6.10 前端工程化

新增可读源码：

```text
apps/owner/ui/
  main.tsx
  api.ts
  interaction-types.ts
  interaction-store.ts
  InteractionHost.tsx
  ModelSelectSheet.tsx
  ResumeDirectorySheet.tsx
  Composer.tsx
  CommandPalette.tsx
  viewport.ts
```

采用：

- Preact 10.29.8（现有固定依赖）；
- TypeScript 严格模式和判别联合；
- Vite 构建 Owner bundle，生产只服务本地静态产物；
- Node test/Vitest 用于纯状态与组件测试，Playwright 用于真实浏览器回归。

迁移顺序为 interaction host -> composer/command palette -> header dynamic state -> 其他面板。
现有 transcript DOM、Markdown/TeX、question navigator、Raw/Chat 和 Live tmux 暂作为 imperative
island，由一个窄 adapter 接收状态。每完成一块就删除 `app.js` 中对应监听器与 DOM 写路径，
不保留隐藏旧 renderer。

暂不引入 Zustand 或 XState。首先使用 TypeScript reducer、不可变 snapshot 和 request
generation；只有出现经过测试证明的嵌套并发状态爆炸时再单独评估状态机依赖。

### 6.11 移动端 VisualViewport

新增纯函数根据 layout viewport、visual viewport height 和 `offsetTop` 计算 footer 位移：

```text
shiftY = clamp(visualHeight - layoutHeight + offsetTop, -layoutHeight, 0)
```

通过 CSS custom property 仅修正文档滚动模式的 composer；使用 rAF 合并 visualViewport
resize/scroll、window resize/orientation 和 focus 事件。键盘关闭时必须回到 0，不能依赖 blur
改变输入器基础宽高。

## 9. 验收标准

必须全部满足：

1. `/model` 在网页中提供可用选择，真实 tmux TUI 同步改变，且不生成聊天 turn。
2. 恢复线程不再卡在目录选择或 `session unknown`；用户可安全选择新目录。
3. 所有已识别菜单以结构化 interaction 展示；未知菜单仍有清晰、可取消的安全 fallback。
4. 刷新/重连恢复当前 pending state，旧 interaction 永远不能控制新状态。
5. 移动端 composer 在实际软键盘开关与 offset 变化时贴近可视区域且不跳动。
6. Owner 交互壳有可读 TypeScript/Preact 源码；被迁移的旧实现已删除。
7. Markdown/TeX、历史、复制、Raw/Chat、Live tmux、发送幂等、附件、认证和 tmux 几何全部
   通过回归。
8. 公开 diff 和测试夹具没有用户身份、域名、Token、Cookie、真实会话正文或本机私有路径。
9. 当前 Codex slash inventory 全部被分类；`/usage` 等本地 panel 不再经过普通消息确认。
10. Goal 详情可按需查看；隐藏目录可切换；活动 Git worktree 不再错误显示永久 `git --`。
11. Codex TUI 可见的合法顶层 legacy/migrated 历史可在 Faryo 搜索并恢复，子代理记录仍隐藏。

## 10. 回滚与发布

- 开始实现前以当前 `v1.5.2` 标签作为完整代码回滚点，不建立长期重复功能分支。
- 每阶段形成可独立审查的提交；迁移后的旧实现通过 Git 历史回滚，不在生产包中隐藏保留。
- 若 interaction 服务不可用，页面只允许明确标记的 Raw/TUI fallback，不把未知状态当 ready。
- 数据目录、rollout、tmux、认证和附件格式不做不可逆迁移；回滚程序无需修改用户数据。
- 仅在完整 source/browser/真实部署门通过后更新版本并发布 v1.6.0。
