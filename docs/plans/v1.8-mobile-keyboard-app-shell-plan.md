## 1. 问题结论

v1.7.1–v1.7.3 的实机回归证明：用 `window.innerHeight`、`VisualViewport.height`、
`offsetTop`、固定 footer 的 `getBoundingClientRect()` 和阈值推断 Android Edge 的键盘、地址栏
与布局视口关系不可靠。页面恢复、地址栏显隐和软键盘动画可能改变不同坐标系的基线；继续
调整像素或阈值只能把一种设备状态修成另一种状态的回归。

当前特殊路径在窄屏 Gateway 会话中把 `window` 作为 conversation scroller，把 `.app` 和
`main` 改回文档流，再把 footer 变为 `position: fixed`，最后由 JavaScript 平移 footer 并扩大
主区 padding。这使 composer、历史锚点、问题导航和浏览器 chrome 同时依赖一组推断值。

本计划把正确性改成布局不变量：composer 由聊天壳的底部网格轨道锚定；消息区是唯一可滚动
区域并延伸到透明 footer 后方；浏览器用 `interactive-widget=resizes-content` 缩小 layout
viewport。footer 的真实内容高度只用于保留最新消息的可滚动尾部空间，任何路径都不根据
设备像素猜键盘高度。

Android Edge 151 的无线 ADB/CDP 真机 A/B 进一步否定了原计划的 VirtualKeyboard overlay
增强：overlay 状态下 `innerHeight=652`，API/CSS 同时报出 357 px 键盘高度，第四网格行因而
把 footer 停在 295 px；同页关闭 overlay 并恢复 `resizes-content` 后，浏览器把
`innerHeight` 缩到 346 px，三行 App Shell 的 footer 正好落在 346 px，截图中的空白区立即
消失。这不是缓存、对话内容或设备像素问题，而是 Edge 浏览器工具栏与 VirtualKeyboard
overlay 坐标组合没有形成可用的页面契约。

## 2. 依据与参考边界

- Chrome/W3C VirtualKeyboard API 定义 `navigator.virtualKeyboard`、`overlaysContent`、
  `geometrychange` 和 keyboard inset；v1.8.0/v1.8.1 按该契约实现，但真实 Edge 工具栏组合未
  达到产品验收，因此这些资料只保留为被实机否定的实验依据：
  <https://developer.chrome.com/docs/web-platform/virtual-keyboard>、
  <https://w3c.github.io/virtual-keyboard/>。
- Chromium 的 `interactive-widget=resizes-content` 由浏览器直接缩小布局视口，是 v1.8.2 的
  唯一生产路径：<https://developer.chrome.com/blog/viewport-resize-behavior>。
- CSS Viewport 规范说明 `VirtualKeyboard.overlaysContent=true` 覆盖 `interactive-widget`；
  v1.8.1 虽已对齐两份声明，仍未通过真机，说明规范一致不等于该 Edge 组合可用：
  <https://drafts.csswg.org/css-viewport/#interactive-widget-section>。
- Vercel Chatbot 使用 `h-dvh` 应用壳、`min-h-0` 会话区和正常组件树中的 sticky composer：
  <https://github.com/vercel/chatbot/blob/main/components/chat/shell.tsx>。
- DeepSeek Harness 的会话壳保持一个长期存在的 scrollport，并把消息流和 sticky composer
  stack 放在同一生命周期边界：
  <https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-conversation/README.md>。

这些项目提供结构参考，不代表它们在所有移动浏览器上已经无缺陷。框架负责 DOM 身份、状态
和事件；键盘几何仍由 Web 平台契约负责。本阶段继续使用现有 Preact，不引入 React 或仅为
键盘位置增加第三方库。

## 3. 目标

1. Owner 使用一个 `100dvh`/可用视口 App Shell：header、`minmax(0, 1fr)` conversation 和
   composer 三行。
2. composer 保持 Grid 锚定而不使用 `position: fixed`、Y transform、键盘阈值或设备补偿
   像素；conversation 跨越 composer 轨道，footer 外围透明。输入区实际高度成为动态尾部
   reserve，展开尺寸在 idle/focus/blur 中保持一致，粗指针聚焦态底部只保留系统 safe-area
   与现有焦点环所需的 6 px 最小净空。
3. 始终声明 `interactive-widget=resizes-content`；若浏览器暴露 VirtualKeyboard API，显式
   把 `overlaysContent` 设为 `false`，防止旧页面状态或其他脚本重新进入 overlay。
4. 只保留一个 conversation scroller。历史前插、尾部跟随、问题跳转、离屏富正文和连续
   实时输出全部以该滚动区为坐标根。
5. 正常标签页、安装 PWA 和用户手势 Fullscreen 的责任清晰。应用不得宣称能强制隐藏浏览器
   地址栏；普通标签页优先保证输入可靠，沉浸式无地址栏由 PWA/Fullscreen 提供。
6. 删除被替代的 document-scroller、VisualViewport dock、CSS 位移变量和 v1.7 阈值路径，
   不长期保留两套同功能代码。

## 4. 非目标

- 不迁移 Owner/Gateway 后端，不改变 Codex App Server、可靠发送或认证协议。
- 不为该问题引入 React、TanStack Virtual、Radix 或键盘 polyfill；它们不能替代浏览器键盘
  几何契约。
- 不保证普通浏览器标签页的地址栏总是自动隐藏；这是浏览器 chrome 行为。
- 不修改 tmux session、pane 宽高、Codex TUI 或现有会话工作目录。
- 不用真实对话正文作为浏览器夹具，也不向服务端发送键盘遥测。

## 5. 目标架构

```text
Owner App Shell (100dvh / usable viewport)
├── Header                         normal row
├── Conversation scrollport       spans body + composer tracks, overflow: auto
└── Composer                       bottom Grid track, transparent surroundings
    └── measured tail reserve      keeps latest content above prompt shell
```

### 5.1 Chromium/Edge 生产路径

viewport meta 始终使用 `interactive-widget=resizes-content`。若浏览器暴露
`navigator.virtualKeyboard.overlaysContent`，controller 显式设为 `false`；CSS 不读取
keyboard inset，也不存在第四网格行。`visualViewport`/window resize 事件只调度一次尾部
锚定更新，不参与键盘高度或 footer 坐标计算。

### 5.2 安全降级

viewport meta 让支持该声明的浏览器缩小 layout viewport，App Shell 的 `100dvh` 随之变化。
若目标浏览器忽略该声明，仍保留可输入、可滚动和不丢消息的安全降级；不恢复 overlay、设备
阈值或 footer 平移。

### 5.3 滚动所有权

`main`/`outputWrap` 是唯一 conversation scroller。HistoryController、QuestionNavigator、
RichBlockController、tail pinning 和 scroll snapshot 全部接收同一元素。窗口滚动不再参与
会话定位；页面根保持 `overflow: hidden`。PWA/Fullscreen 与普通标签页使用同一布局树。

## 6. 实施阶段

### 阶段 A：隔离布局门禁

- 新建小型 `keyboard-layout` controller，只负责强制 viewport-resize 契约、合并 resize 通知和
  清理；无 footer 坐标算法。
- 用 DOM/浏览器夹具覆盖 API 支持/API 缺失、旧 overlay 复位、destroy、旋转/resize 与
  safe-area。
- 建立匿名长消息夹具，验证 viewport 收缩时 composer 不离开 grid、conversation 可视高度变化、
  尾部用户保持尾部而旧历史读者位置不被抢走。

### 阶段 B：生产 App Shell

- 把窄屏 `.document-scroll-mode` 特殊树替换成与桌面一致的 grid/flex App Shell。
- composer 从 fixed footer 迁回 Grid 管理；conversation 跨越其轨道，footer 保持透明，并以
  `ResizeObserver` 同步状态行、附件、命令菜单、错误和输入自动增高产生的真实 reserve。
- 统一 `conversationScroller = outputWrap`，调整 observer root、历史锚点和滚动按钮坐标。
- 在键盘几何变化时只调度一次布局后的尾部恢复，不用定时等待或循环刷新。

### 阶段 C：旧代码删除

- 删除 `createDocumentScroller`、`shouldUseDocumentScroller`、`visualViewportShift`、
  `visualViewportSnapshot`、`createVisualViewportDock` 及相应测试。
- 删除 `document-scroll-mode`、`--faryo-visual-viewport-*`、keyboard padding 补偿和基线阈值。
- 更新 v1.7 计划为历史证据，明确其启发式已由 v1.8 替代，而不是继续作为生产分支。

### 阶段 D：回归、部署和实机

- 运行 Ruff、格式、类型、依赖、Owner/Gateway/CLI、浏览器 bundle 和匿名长历史门禁。
- 验证发送幂等、附件、slash/interaction、Raw/Chat、Markdown/KaTeX、复制、Live tmux、
  PWA/Fullscreen 和普通 reload。
- 版本化安装 v1.8.0，部署前后逐项比较 tmux 窗口几何并检查服务日志。
- Android Edge 实机覆盖：普通标签、地址栏显示/隐藏、键盘开关、输入自动增高、页面恢复、
  横竖屏、回到前台和长历史阅读。只在该门通过后完成计划、推送 main。

## 7. 验收不变量

- composer 由 App Shell 底部 Grid 轨道锚定；生产 CSS/JS 不存在 fixed footer 或键盘相关固定
  Y 位移，透明外围的 computed background 必须为全透明。
- 生产 DOM 不含 keyboard inset 网格行，VirtualKeyboard overlay 始终关闭。
- composer 不被键盘或浏览器内容视口遮挡，不悬浮在会话中部，也不依赖设备型号。
- 粗指针聚焦态 `promptShell.bottom` 与 App Shell 可用底边相差 6 px；0 px 真机 A/B 会裁掉
  3 px 焦点线、2 px offset 和圆角，因此不作为可发布状态。
- 键盘打开/关闭时，尾部读者仍看到最新消息；阅读旧历史者的锚点误差不超过 3 px。
- 普通 reload 或新标签页取得新版本；不要求硬刷新。
- 真实发送只提交一次，失败保留草稿；结构化历史、Markdown/TeX 和 Live tmux 无回归。
- 部署前后每个既有 tmux window 的宽高一致，Owner/Gateway 健康且日志无新错误。
- 公开提交不包含真实会话、身份、凭证、私有域名或本机路径。

## 8. 回滚与发布

v1.8.3 作为当前上一安装版本保留在版本化目录中，v1.7.3 仍是更早的稳定回退点。任何
health、browser 或实机门失败都可回滚应用版本而不停止 Codex/tmux。完成后只保留 v1.8.4
生产路径；Git 历史和版本化安装目录提供恢复能力，不用并行 feature flag 承担永久维护成本。
