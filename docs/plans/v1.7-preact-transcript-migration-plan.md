# Faryo v1.7 Preact Transcript Migration Plan

计划索引：[`README.md`](README.md)

状态：已完成并部署为本机 v1.7.0 source candidate

更新时间：2026-08-21

范围：Owner 会话页的页头身份、移动端键盘几何、结构化对话状态、长历史渲染与问题导航

隐私：计划、夹具和性能证据只记录匿名状态、节点计数与耗时；不记录账号、域名、Token、
Cookie、真实会话正文或本机绝对路径。

## 1. 现状与问题

Faryo 不是零依赖前端。输入区、命令面板、状态栏和结构化 Codex 交互已经使用固定版本、
本地打包的 Preact；Markdown/TeX、代码高亮和安全 diff 也分别使用成熟库。当前维护风险集中
在 Owner 对话主流程：大型原生 `app.js` 同时编排网络代次、历史分页、流式捕获、滚动、
Raw/Chat、Live tmux、问题导航和手写 DOM。

本阶段从两项可见回归开始：

1. 折叠页头中的工作站短名称是不可收缩 flex 项，固定胶囊宽度不足时文字贴住或越过右侧
   圆角；修复必须适用于任意短名称，不能写死某台机器。
2. Android/Edge 弹出软键盘后，固定 composer 根据 VisualViewport 推到过高位置，但对话
   可视区和尾部锚点没有使用同一份几何，造成输入框与历史割裂。

长对话专项已经通过离屏释放富 Markdown/KaTeX body，把真实压力页从约 43,000 个元素降到
约 4,800 个。这个优化继续保留。下一步不是盲目把所有消息交给框架，而是先建立可测试的
状态边界，再判断外层消息数量是否仍需要 TanStack Virtual。

## 2. 目标

1. 修复折叠页头的名称安全间距、收缩和省略规则，并覆盖窄屏、字体放大和较长名称。
2. 让 composer、对话可视区、底部留白和尾部跟随共享同一份 VisualViewport 快照；键盘
   出现时不双重位移，不遮住最新回答，也不强制把正在阅读旧历史的用户拉回底部。
3. 建立框架无关的 `ConversationStore`：统一 session generation、显示模式、历史状态、
   capture revision、连接阶段和不可变快照；旧会话的迟到响应不得污染新会话。
4. 将结构化 transcript 外壳和高风险状态分支渐进迁入 Preact/TypeScript，保留现有
   Markdown AST、KaTeX、复制来源、Live tmux 和富正文离屏 controller 作为受控适配器。
5. 对外层 turn/message 列表进行 TanStack Virtual 测量型试点。只有在节点数、长任务、
   内存和交互正确性全部优于现状时进入生产路径；否则保留试验和结论，不增加运行包袱。
6. 普通重新加载或新标签页必须取得新资产，不要求硬刷新；不改变 Owner/Gateway 认证、
   可靠发送、附件、Codex 交互协议或 tmux/TUI 几何。

## 3. 非目标

- 不迁移后端，不把 Faryo 改造成 DeepSeek Harness，也不复制其品牌或插件体系。
- 不用一次性 React SPA 重写替代现有 Preact；不同时维护两套同功能生产 transcript。
- 不重写已经通过回归的 Markdown/TeX AST、源文本复制和 Codex JSONL 读取。
- 不因为虚拟化删除完整逻辑历史、问题索引或服务端分页。
- 不在公开仓库保存真实长对话内容或浏览器身份信息。

## 4. 设计原则

### 4.1 状态层先于组件层

网络、历史和 Codex 事件先进入框架无关 store，Preact 只消费不可变 snapshot。每次切换
session 都增加 generation；异步结果提交前核对 generation、session 和 revision。这个边界
参考成熟会话客户端的“持续事件对象 + 快照订阅”设计，但保持 Faryo 的单用途规模。

### 4.2 一个状态只有一个所有者

- store 拥有会话和 transcript 生命周期；
- Preact 拥有已迁移区域的 DOM；
- Markdown/KaTeX renderer 拥有单条富正文；
- virtualizer 若通过门禁，只拥有外层行的范围、测量和滚动锚点；
- tmux 只是运行证据，不参与浏览器布局。

迁移一个区域后删除被替代的原生 DOM 分支，禁止 Preact 与旧代码同时写同一节点。

### 4.3 虚拟化采用聊天语义

试点使用稳定 message key、动态 `measureElement`、少量 overscan、尾部锚定和仅在原本位于
尾部时跟随新增内容。历史前插、流式尾项增高、宽度变化和字体加载都必须保持锚点；问题
跳转可以恢复未挂载目标。富正文 controller 与外层 virtualizer 不得同时测量同一层高度。

## 5. 实施阶段

### 阶段 A：几何与可见回归

- 为折叠身份胶囊增加可收缩文本槽、明确的左右安全间距和响应式最大宽度。
- VisualViewport controller 输出单一快照：可见顶部/底部、高度、实际 dock 位移和遮挡量；
  通过实测 footer 基准位置避免浏览器已经移动 fixed 元素时再次位移。
- 键盘开启且用户原本在尾部时，更新底部保留空间后恢复尾部；阅读旧历史时保持当前位置。
- 增加纯函数、DOM 和移动 viewport 浏览器回归。

### 阶段 B：ConversationStore

- 定义 TypeScript 判别状态和纯 store，覆盖 loading、ready、empty、fallback、error、
  compact/raw、history prepend 和 live revision。
- 让 capture/history/event-stream 通过命令更新 store；组件不直接发网络请求。
- 为 session 切换、旧响应隔离、重复 revision、断线恢复和 mode round-trip 增加测试。

### 阶段 C：Preact transcript 外壳

- 新增 `TranscriptShell`、错误边界和 keyed block view；先迁移 loading/empty/fallback、状态警告
  和稳定 block 外壳。
- 用窄适配接口调用现有 Markdown/KaTeX、复制和 rich-body controller。
- 删除对应的模板字符串、`innerHTML` 状态分支和重复监听器。

### 阶段 D：TanStack Virtual 门禁试点

- 固定兼容许可版本并本地打包；优先使用 framework-neutral `virtual-core`，不额外引入 React。
- 使用匿名 40-turn、200-turn 和复杂 Markdown/KaTeX fixture 对比：初始渲染、快速滚动、
  DPI/窗口变化、历史前插、问题跳转、尾部流式增长、复制和浏览器查找降级。
- 生产采用门槛：挂载 DOM 有界；4 倍 CPU 下 resize/快速滚动没有超过 100 ms 的新增长任务；
  锚点误差不超过 3 px；内存和 bundle 增量有记录；无功能回归。

### 阶段 E：部署与清理

- 运行格式、类型、依赖、JavaScript、Python、浏览器和真实服务检查。
- 普通 reload 与新标签页验证资产版本；验证手机键盘、桌面缩放和真实长会话。
- 确认所有既有 tmux session 和 pane 几何未改变，再部署并更新证据。
- 删除试点失败路径或已替代代码，不留下永久 feature-flag 分叉。

## 6. 验收标准

- 320 px 宽、字体放大两级时，任意 3–12 字符工作站名称仍位于胶囊安全区内。
- Android/Edge 键盘开关、地址栏变化、翻译栏和旋转期间，composer 位于可见视口底部；最新
  回答可见且旧历史阅读位置不被抢走。
- 快速切换 session、Raw/Chat 和历史分页时，无旧响应覆盖、空白 transcript 或重复消息。
- Markdown、KaTeX、代码、图片、内部引用、跨块复制、Live tmux、完整问题导航全部通过。
- 长历史的 DOM、长任务和滚动锚点至少不弱于 v1.6.8 基线。
- `faryo doctor`、Owner/Gateway health 和真实发送通过，tmux/TUI 宽高保持原值。
- 所有公开文档和夹具通过隐私检查，普通刷新即可使用新版本。

## 7. 当前进度

- 已确认当前前端是原生 DOM 与局部 Preact 的混合架构，不需要引入第二套 React runtime。
- 折叠页头已改为固定图标、可收缩名称和明确右侧安全区；320 px 与字体放大夹具通过。
- VisualViewport controller 现在同时输出实测 dock 位移和键盘遮挡量：浏览器已经移动 fixed
  footer 时不再二次补偿，历史区共享同一遮挡量；纯函数和浏览器几何夹具通过。
- 新增框架无关 `ConversationStore` 和 Preact `TranscriptShell`。session、generation、mode
  共同隔离轮询/SSE 迟到响应；loading、starting、empty、terminal fallback 与 render error
  不再由分散的 `innerHTML` 状态分支拥有。Preact 状态更新不会清除适配器管理的正文 DOM。
- TanStack Virtual 3.17.8 临时门禁使用匿名 600 行、当前“全部轻外壳 + 少量富正文”模型：
  挂载节点由 1,344 降为 251，24 次宽度测量由约 31.1 ms 降为 7.4 ms，运行包预计增加约
  6.7 KiB gzip；但 Preact/core 试验适配器的历史前插没有保持 3 px 锚点，因此未进入生产。
  临时依赖和失败适配器已经移除。Faryo 继续使用真实长会话已通过的富正文离屏释放；外层
  virtualizer 只有在不可变列表生命周期和前插锚点同时通过时才重新评估。
- Canonical source gate 通过 Owner 199、Gateway 117、CLI 57 个 Python 测试，以及 Ruff、
  ESLint、格式、依赖、TypeScript、bundle 和浏览器模块检查。捕获 controller 的轮询与 SSE
  都有独立的 obsolete-scope 回归。
- 匿名 40-turn Markdown/KaTeX 浏览器矩阵仍为 5 个富正文、75 个 deferred body、2,580 个
  后代节点；完整分页、问题导航、Chat/Raw 和 tmux 几何通过。
- 版本化安装器已从干净提交切换本机到 v1.7.0，manifest 与提交一致；`faryo doctor` 为
  22 OK、0 warning、0 failed，Owner/Gateway 健康。部署前后的 6 个 tmux session 及每个
  `145×44`/`80×24` 窗口逐项相同。
- 部署后普通新标签页在 390×844 Chromium 与 1440×900 Edge 验证真实结构化历史、KaTeX
  和布局；Chat/Raw round trip 通过。拦截式空线程夹具在普通 reload 后仍为 Preact `empty`
  状态，无终端启动文本或 fallback 泄漏。真实 Android 软键盘无法由桌面自动化生成，相关
  修复由 VisualViewport 纯函数、实测 dock 模拟和移动 CSS 浏览器夹具共同覆盖。
