## 1. 目标

在不改变 Faryo 运行架构和安全边界的前提下，把 Owner 会话页完善为受
DeepSeek Harness 启发的现代 Agent 工作台：桌面端具有清晰、安静的对话主轴，
移动端能够单手切换会话、查看状态、阅读 Markdown/TeX、观察实时执行并可靠地
向现有 tmux/Codex 或 Claude TUI 提交内容。

最终结果必须同时满足：

1. 对话阅读体验明显改善，但仍然是 Faryo 自己的视觉身份。
2. 360--430 px 手机宽度不是桌面布局的压缩版，而是独立设计的单栏工作流。
3. 已经解决的认证、实时同步、输入确认、公式渲染和滚动问题不得回归。
4. 不修改 tmux 窗口尺寸、Codex/Claude TUI 宽度或终端自动换行行为。
5. 公开仓库中不出现真实 Token、Cookie、邮箱、域名、会话内容或本机私有路径。

以下能力是新版 UI 的回归基线，不因视觉重构而改变：

| 能力 | 冻结要求 |
| --- | --- |
| Owner/Gateway 认证 | 所有读取和写请求继续携带正确认证；不得将凭据写入 DOM、日志或仓库 |

## 4. 目标信息架构

### 4.1 桌面与宽屏平板（宽度不小于 960 px）

采用三层但非强制三列的工作台：

```text
会话导航（可折叠） | 居中对话主轴 | 按需打开的详情面板
                    | 固定浮动输入器 |
```

- 会话导航用于切换活动会话和返回 Gateway，不承担文件管理器职责。
- 对话主轴的理想阅读宽度为 720--780 px，宽屏不再把消息扩展到整个视口。
- 详情面板默认关闭，用于 Raw、执行状态、附件和会话元信息。
- 工具/过程/Live tmux 是可折叠的执行证据，不与最终回答争夺视觉层级。
- 输入器保持居中、稳定、可扩展，发送、附件和中断状态始终可辨认。

### 4.2 手机（宽度小于 720 px）

手机采用真正的单栏布局：

```text
轻量顶栏
对话正文
回到最新按钮
稳定的大输入器

会话列表 -> 左侧全高抽屉
详情/Raw -> 全屏面板或底部面板
```

- 不保留占据正文宽度的折叠侧栏。
- 顶栏只展示会话标题、运行状态和菜单入口。
- 正文左右留白 10--12 px；用户消息不超过可用宽度的约 88%。
- 输入器在 focus、blur 和软键盘开关后保持相同的基础高度；只随真实文本行数增长。
- 表格、显示公式和代码块在自身容器内横向滚动，不撑宽整个页面。
- Live tmux 默认折叠并显示“正在执行”摘要；用户主动展开后尊重内层滚动位置。
- 所有主要触控目标至少 44 px，并适配顶部、底部安全区。

### 4.3 中间宽度（720--959 px）

- 保持单个对话主轴。
- 会话导航使用覆盖式抽屉，不挤压中心内容。
- 详情使用覆盖式侧面板；关闭后中心内容恢复原宽度。

## 5. 技术路线

### 5.1 保留的架构

- Python Owner/Gateway 服务和现有 API 路径不变。
- 结构化会话读取、SSE 刷新、tmux 输入与 Raw 路径不变。
- 浏览器外壳可继续使用原生 HTML/CSS/JavaScript，但允许引入构建工具和模块化源码；
  不引入 Node 生产运行时。
- 继续使用仓库内 KaTeX 和字体资源。旧 `markdown-it`、数学 DOM 后处理和宽泛正则修补
  仅在迁移期间用于对照；新管线验收后从生产页面和仓库运行时代码中删除。回滚依靠
  `pre-deepseek-ui-20260815` 标签和备份分支，而不是永久维护两套实现。

### 5.2 Markdown/TeX 引擎决策（2026-08-15 更新）

用户明确选择“渲染效果第一位”。阶段 D 因此采用与 DeepSeek Harness 同类的
AST 管线，而不是继续以正则修补现有渲染器：

```text
原始结构化消息
  -> micromark（CommonMark tokenization）
  -> mdast（Markdown AST）
  -> GFM 扩展（表格、任务列表、删除线、自动链接）
  -> math 扩展与兼容层（$、$$、\(...\)、\[...\]）
  -> 安全 HTML renderer
  -> KaTeX 数学节点
  -> 可选代码高亮
```

实施约束：

- 依赖版本和生成命令锁定；浏览器只加载仓库内的预构建 bundle，不要求生产机
  安装 Node 或联网。
- 新引擎先在隔离夹具中与旧实现 A/B；通过验收后成为唯一生产实现，不暴露长期旧引擎
  开关，也不让每次功能修改承担双实现成本。
- 借鉴或复用 DeepSeek Harness 的 math compatibility 源码时，固定上游提交、保留
  MIT 归属，并在仓库许可证说明中记录；不复制其品牌资源。
- AST 到 HTML 的过程使用允许列表；原始 HTML、危险协议、事件属性和任意文件 URL
  不因换引擎而放开。
- 流式阶段只渲染已经闭合且语法稳定的块；最终阶段启用完整 GFM 与数学解析，避免
  未完成的 TeX/代码围栏造成闪烁或吞掉后续正文。
- 代码高亮作为同一阶段的第二步。优先采用 Harness 的 Shiki 按需语言方案；首屏仅带
  常用语法和基础主题，其余语言在代码块实际出现时加载，加载失败仍保留正确的代码
  AST 与纯文本样式。

### 5.3 Harness 技术审查与采用原则

不是把 Harness 的 React 页面整体搬进 Faryo，而是按问题边界吸收已经验证的方案。
固定提交审查形成以下实施队列，完成一项就在本文记录对应提交和验证证据：

| Harness 方案 | Faryo 决策 | 原因与落点 |
| --- | --- | --- |
| `micromark -> mdast`，GFM 与 math extension | 立即采用 | 用语法树界定表格、代码、正文和公式，替代 DOM 猜测；阶段 D 核心 |
| streaming 只解析 GFM，settled 再启用 math | 立即采用 | 未闭合 TeX 不产生闪烁和 KaTeX 错误；与结构化最终消息边界配合 |
| `mathCompatibility` 与 `cjkFriendlyStrong` | 固定提交、保留 MIT 归属后采用 | 覆盖 `\\(...\\)`、`\\[...\\]`、同行 `$$...$$` 和中文标点后的粗体 |
| 增量解析中冻结稳定顶层块，只重算尾部 | 阶段 D 后半采用 | 降低长对话频繁刷新时 DOM 抖动与重复解析成本，同时尊重用户滚动位置 |
| Shiki 常用语言预热、其余懒加载 | 采用 | 代码效果优先，同时避免把完整语言库压入手机首屏 |
| AST 直接 renderer、URL 协议允许列表、原始 HTML 文本化 | 采用并扩展 | 保留 Faryo 本地文件回调，同时不放开 XSS、任意图片或危险协议 |
| 追加事件日志、每会话游标、尾页基线、seq 缺口修复和 reconnect generation | 按 Faryo 边界适配 | rollout 以文件身份和字节偏移充当游标，半行不提交，SSE 重连重新取得完整尾部快照；旧 HTTP 响应用 run id 丢弃 |
| React/Cordis 整体应用壳 | 不直接采用 | Faryo 当前 Owner/Gateway 生命周期与认证不同；只有在原生状态层成为明确瓶颈时再单独论证 |
| DeepSeek 品牌、图标和文案 | 不采用 | 保持 Faryo 独立身份，避免误导和不必要的品牌复制 |

审查还要覆盖 Harness 的长列表/流式消息更新、错误边界、代码复制、移动端面板和状态
恢复做法。任何新增依赖必须说明：解决什么问题、首屏成本、离线行为、安全边界、固定
版本、许可证以及怎样测试；不能因为“对方用了”就直接引入。

### 5.4 前端隔离策略

- 在页面根节点加入明确的新版 UI 标识，新增设计令牌只在 Owner 会话页生效。
- 先新增布局容器和语义化控制，不删除旧 ID；现有 JavaScript 查询和 API 行为因此
  保持兼容。
- CSS 按“令牌 -> 外壳 -> 组件 -> 响应式 -> 可访问性”组织，避免继续扩大单行规则。
- 新交互状态由小型纯函数管理并增加 Node 测试；不把布局状态混入认证/发送状态机。
- 每个阶段形成独立提交，阶段验收失败时回退单个提交，而不是回退整个功能分支。

### 阶段 B：响应式导航和详情面板（P0）

范围：Owner `index.html`、`app.js`、`style.css`，必要时增加独立布局模块和测试。

- 新增桌面折叠导航入口，但不复制 DeepSeek 品牌或图标。
- 将 Raw、会话信息和附件状态组织到按需详情面板。

- 实现焦点圈定、Escape 关闭、背景滚动锁定和返回焦点。
- 切换会话前持久化当前草稿，并保持现有选中会话 URL 语义。

验收：

- 键盘、触屏和屏幕阅读器均能打开、浏览和关闭面板。
- 360 px 下会话抽屉不挤压正文，44 px 触控目标无重叠。
- 切换会话不丢草稿、不重复订阅、不泄露上一会话内容。

### 阶段 C：执行过程和 Live tmux（P1）

范围：compact rules、`app.js`、`live-scroll.js`、样式与测试。

工作项：

- 将 process、plan、状态和 Live tmux 表现为可折叠执行卡。
- Agent 运行时展示轻量状态摘要；最终结构化回复到达后自动收敛。
- 保存用户对 Live tmux 的展开状态，但不同会话之间不共享内容状态。
- 展开状态变化不触发主对话强制滚动；已有内层滚动算法继续工作。

验收：

- 高频 live 更新不会把用户从历史阅读位置拉回顶部或底部。
- 展开/折叠时主对话累计布局偏移可接受。
- Raw 始终能提供原始终端证据，Compact 不伪装成完整终端。

### 阶段 D：成熟 Markdown/TeX 管线（P0）

范围：`tools/markdown-engine`、`vendor/markdown-ast`、`stable-blocks.js`、`app.js`、
渲染测试、发布清单和许可证文件。

工作项：

- 以锁定依赖构建浏览器端 `micromark + mdast + GFM + math` bundle，并记录许可证、
  构建命令和 bundle 校验方式。
- 新旧引擎在独立夹具中完成短期对照；新实现通过验收后删除旧生产脚本、依赖和分支逻辑。
- 建立明确的 `streaming` 与 `settled` 两种渲染模式。
- `streaming` 对未闭合 Markdown、代码围栏和数学定界符采取保守显示，不闪现错误公式。
- `settled` 完整解析 GFM、表格、链接、图片、代码块和 TeX。
- 为 LaTeX 环境、`\[...\]`、`\(...\)`、`$$...$$`、`$...$` 以及终端受损输入建立
  不互相冲突的优先级。
