# Faryo Codex Command Completion Plan

更新时间：2026-08-19
状态：排队中；等待 Start Codex Runtime 完成后开始

## 问题基线

Owner 输入框目前只硬编码少量 slash/launch 建议。用户输入 `/` 或 `codex` 时看到的候选
远少于当前 Codex CLI 实际提供的命令，命令参数、说明和版本来源也不可审计。

## 目标

1. 对齐本机当前 Codex CLI 交互面板中可供用户使用的全部内置命令。
2. 候选包含命令、简短说明、参数提示、类别和是否需要额外确认，不只是一串名称。
3. 支持前缀、模糊匹配、键盘上下选择、Tab/Enter 补全和 Escape 关闭。
4. 手机触控候选可滚动，不遮挡输入框、不改变 composer 固定大尺寸。
5. Codex 升级后能够用可重复实验重新生成/核对命令清单，而不是继续手工遗漏。

## 命令发现方法

采用与 DeepSeek Harness 工程审查相同的隔离实验原则：

- 固定被测 Codex CLI 版本和可执行文件摘要；
- 在临时目录、临时 tmux 和无真实会话内容的 PTY 中打开 `/` 命令面板；
- 只采集命令名称、公开说明和参数形状，不执行会修改账号、权限或工作区的命令；
- 与 CLI `--help`、可用官方源码/文档和现有交互面板三方交叉核对；
- 将匿名快照转换为仓库内可审查的数据模块，并提供差异检查；
- Harness 只作为实验与交互设计参考，不引入其运行时、品牌或远程依赖。

如不同 Codex 版本、权限状态或功能开关显示不同命令，清单必须记录条件，不把某次实验
结果错误宣称为永远固定的全集。

## 实现边界

- 命令元数据与输入框逻辑分离，避免继续扩张 `app.js` 中的硬编码数组；
- 网页只负责发现和补全文本，不自动执行命令；
- 危险命令不得默认附加确认跳过参数；
- 不记录账号、配额、模型列表、工作区或命令历史；
- 普通自然语言输入和 `cd` 最近目录提示继续正常工作。

## 测试矩阵

1. 数据清单与隔离 PTY 快照逐项一致，无缺失、重复或失效别名；
2. `/`、命令前缀、描述关键词和 `codex` launch 前缀；
3. ArrowUp/Down、Tab、Enter、Escape、鼠标与手机触控；
4. 参数型命令只补全命令骨架，不伪造用户参数；
5. 危险/状态相关命令有清晰标识但不自动运行；
6. 390x844 与 1440x900 布局、焦点、composer 高度和草稿保持；
7. 现有发送、附件、公式、历史和问题导航回归。

## 验收标准

- 当前被测 Codex CLI 的所有可见内置命令均可在网页发现；
- 清单来源、版本和再生成步骤可审计；
- 候选交互在手机与桌面浏览器通过；
- 不新增外部运行依赖、不泄露本地状态、不降低权限安全；
- 完成后记录命令数量、差异、提交和浏览器证据，并移入 Completed。
