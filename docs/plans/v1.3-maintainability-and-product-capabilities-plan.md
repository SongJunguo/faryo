# Faryo v1.3 Maintainability and Product Capabilities Plan

更新时间：2026-08-20
目标版本：v1.3.0
状态：完成并部署

## 目标

v1.3.0 不以“增加依赖数量”为目标，而是用合适的成熟库替换已经产生明显维护成本的自研
部分，并落地几项移动监督真正需要的能力：

1. 用 Playwright/Ruff 收敛浏览器测试和 Python 质量门禁；
2. 把 Gateway portal 的 CSS/JavaScript 从 Python 拆出，并在有可量化收益时采用 Floating UI；
3. 增加版本化 capability、脱敏 diagnostics 和 workspace-scoped 只读 Git changes/diff；
4. 增加不含消息正文的 attention center 与安全通知基础；
5. 只通过 Codex 正式协议实现 steering/queue 控制，不解析脆弱 TUI 文本冒充可编辑队列。

## 不变边界

- Codex-only；不恢复 Claude、多 provider 或旧二进制打包路径；
- Owner/Gateway 继续 loopback，Cloudflare/inner login、CSRF 与 Owner token 注入不减弱；
- 不在公开仓库写真实域名、邮箱、Token、Cookie、会话正文、session id 或私有绝对路径；
- diff/diagnostics 只读、workspace-scoped、严格限长，不成为任意 shell/file API；
- notification 不含 prompt、answer、标题、路径、原始 ID 或凭据；
- 不修改 tmux/Codex TUI 尺寸；移动 document scroll、PWA、Fullscreen、公式和可靠发送必须回归。

## 依赖采用门槛

每个新依赖都必须记录：

- 上游仓库、许可证、固定版本和 lockfile；
- production/dev-only 分类、打包后字节数和是否增加运行时进程；
- 替代的自研代码/缺陷类型与退出方案；
- 本地 vendored/bundled 资产及 notice；生产不得依赖 CDN；
- canonical CI 与至少一个真实浏览器/接口验收。

## 阶段 A：开发工具

### Playwright

- 使用 `playwright-core` 和现有 Chrome/Edge executable，不下载或发布浏览器二进制；
- 建立共享 browser fixture：临时 profile、认证 header、viewport/touch、可信点击、截图和清理；
- 先迁移 `browser-immersive-smoke.mjs` 与 Gateway workbench smoke，量化删除的 CDP boilerplate；
- 巨型 KaTeX/delivery matrix 只在共享 fixture 稳定后渐进迁移，不一次重写。

### Ruff

- 固定 dev-only 版本和 `pyproject.toml`；
- 第一阶段只启用不会造成全仓格式风暴的明确错误/导入/安全低误报规则；
- 对现有两个大 server 先建立 baseline，再分模块逐步收紧，不为“全绿”批量改写行为代码。

## 阶段 B：Gateway portal 拆分

1. 将 `PORTAL_CSS` 移入 `server/static/workbench.css`；
2. 将 `PORTAL_JS_TEMPLATE` 移入 `server/static/workbench.js`；
3. 动态 route labels 使用 nonce-protected JSON bootstrap，不拼接进 JavaScript 源码；
4. CSP 保持 external `self` asset + 最小 nonce bootstrap；
5. portal 资源使用显式版本和 `no-store`/受控缓存策略；
6. 对当前手写 `placeSheet` 做前后复杂度/碰撞测试。只有 Floating UI 能明显删除定位代码并通过
   390x844/1440x900 visual regression 时才 bundling；否则记录“不采用”。

Preact/Lit 本版本只做 adoption gate，不迁移 Compact Chat。若 Gateway 静态拆分后 session-card、
modal 和 filter state 仍大量重复，选择一个 bounded pilot；否则维持 vanilla modules。

## 阶段 C：Capability 与脱敏 Diagnostics

Owner 提供版本化只读 payload：

- schema/version、release、Codex/App Server 可用性；
- structured history、archive、fullscreen/PWA、document scroll、workspace changes 等 feature flags；
- 服务健康、缓存/会话数量等计数，不含路径、env、Token、标题或正文。

Gateway 只为允许 route 聚合这些字段，并提供下载/复制脱敏 diagnostics 的 UI。任何字段新增都
必须有 privacy test；错误不回显 subprocess command、cwd 或上游响应正文。

## 阶段 D：只读 Changes 与 Diff Review

Owner：

- 从目标 session 的已验证 cwd 开始，向上解析 Git worktree root，但不得越过 workspace root；
- 只允许固定 `git status`/`git diff` argv，无用户可控 revision/pathspec/shell；
- 禁用 pager、外部 diff、颜色和 textconv，设置超时、文件数、行数、单文件/总字节上限；
- symlink、非 Git、超界 root、subprocess failure 使用受控错误；
- payload 不记录审计正文，Gateway audit target 只用现有 HMAC alias。

Browser：

- 采用本地 bundle 的 diff2html 解析/布局，并经过本地 DOM sanitizer；
- 手机默认 line-by-line，桌面可切 side-by-side；大 diff 只显示摘要/截断说明；
- 首版完全只读：不 stage、commit、checkout、discard、apply 或运行任意命令。

## 阶段 E：Attention 与通知基础

- 从现有 Starting/Running/Waiting/Exited/Resumable 状态转换生成 body-free attention item；
- attention 只含 route alias、状态类别、时间和 HMAC target，默认不持久保存正文/标题；
- 网页内提供 unread/needs-action 入口；浏览器 Notification 必须用户明确开启；
- notification 文案只说“session completed / needs attention”，点击绑定精确 route/session；
- v1.3.0 不引入后台 Web Push/VAPID 私钥，先验证同页/PWA notification 和生命周期准确性；
  后台 push 作为独立安全计划。

## Pending follow-up 协议边界

[OpenAI Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)公开：

- `turn/steer` 可向当前 in-flight turn 追加输入，并要求匹配 `expectedTurnId`；
- `turn/interrupt` 可中断 active turn；
- 当前文档没有公开 queued follow-up 的 list/edit/reorder/cancel RPC。

因此 v1.3.0：

- 不从 tmux 文本反推并编辑 Codex 内部队列；
- 不用另一 App Server client 操作由现有 TUI 持有的 active turn；
- 继续展示 Faryo 自己的 pasted/accepted/ambiguous delivery receipt；
- 若本机当前 Codex 协议探测发现未文档化 method，也只记录实验结果，不进入 production；
- 真正 editable queue 等官方协议出现后另立计划。

## 验证矩阵

1. dependency license/version/lock/build reproducibility 与无 CDN；
2. Ruff、source checks、Owner/Gateway Python 和 browser-module tests；
3. Playwright fixture 在系统 Chrome/Edge 的移动/桌面 viewport、touch、auth、cleanup；
4. Gateway external assets 的 CSP、bootstrap、缓存、login/CSRF、历史与 Start Codex；
5. Git root/workspace/symlink/timeout/large diff/adversarial filename；
6. diff renderer XSS、宽内容、手机 line view、桌面 side-by-side、复制；
7. capability/diagnostics 字段 allowlist 与隐私扫描；
8. attention 状态转换、重复抑制、permission denial、精确 deep link 与 body-free audit；
9. 公式、历史、Chat/Raw、Live、发送、图片、Archive/Restore、Edge root scroll/PWA/Fullscreen；
10. 部署前后 Owner/Gateway health 和每个既有 tmux geometry 完全相同。

## 验收标准

- 库实际减少重复代码或风险，并有量化前后对比；
- Gateway Python 不再内嵌 portal CSS/完整 JavaScript；
- diagnostics、changes、attention 都遵守公开 privacy allowlist；
- diff review 可用但没有任何远程 Git 写操作；
- 不伪造 pending queue 能力；正式协议缺失时以明确边界完成；
- canonical/local/browser/deployed/remote CI 全绿后才发布 source-only v1.3.0。
