# Faryo v1.4 Backend Modernization and Modularization Plan

更新时间：2026-08-20
目标版本：v1.4.0
状态：进行中

## 1. 背景与结论

Faryo 当前功能和安全边界已经经过真实 Owner、Gateway、Cloudflare、移动 Edge、桌面
Chrome 和 tmux 会话验证。v1.4.0 的目标不是重写产品，而是让已经稳定的行为不再集中在
四个巨型文件中，并把 Gateway 从 Python 标准库的开发型 HTTP 外壳迁移到生产型 ASGI
外壳。

本版本确认以下技术决策：

1. Owner 继续使用 Python 3.13；tmux、Codex、SQLite、JSONL、文件和可靠发送仍由
   Python 实现；
2. Gateway 业务逻辑继续使用 Python，但 HTTP 层从 `http.server` 迁移到
   Starlette/Uvicorn；
3. 本机和 CI 继续使用 Conda/Python 运行时发现，不引入 uv；普通 `venv + pip` 可以继续
   作为兼容路径，但不成为本版本的新工具链；
4. Owner 前端拆成原生 ES modules，不把实时对话、文字选择、增量 Markdown、Live 和发送
   状态迁移到组件框架；
5. Gateway 主页允许做一个 Preact 受控试点；只有量化收益和完整回归都成立时才进入发布；
6. 不将后端改写为 Node.js、Go 或 Rust。未来若需要单文件分发，可在稳定协议之上另立
   Go Gateway v2 计划；
7. 迁移期间允许 legacy/ASGI 双端口对照，但 v1.4.0 发布代码不得永久保留两套同功能
   HTTP 实现；回滚使用 `v1.3.0` 标签。

## 3. 不变边界

### 3.1 认证与公网

- Owner 和 Gateway 继续只绑定 loopback；公网只通过 Tunnel/Access；
- 保留外层 Access 168 小时、内层 Faryo 24 小时；
- 保留当前精确身份 Allow、Google/GitHub/Email OTP、无 Everyone、无 Bypass、无独立 MFA；
- 保留 Faryo 主机定向 HSTS 31536000 秒和 `nosniff`；不启用 preload 或整个域的
  `includeSubDomains`；
- Owner Token 只能由 Gateway 注入，浏览器和日志不得得到真实值；
- 所有浏览器写请求继续使用会话绑定 CSRF；
- Cookie 名称、签名、epoch revoke、`Secure`、`HttpOnly`、`SameSite=Strict` 和有效期不得
  静默改变；
- 代理继续丢弃 hop-by-hop 头和浏览器伪造的 Owner/Gateway 内部头。

### 3.2 Codex 与 tmux

- Codex-only；不恢复 Claude、多 provider 或旧 project orchestration；
- 不改变 Codex 启动参数和操作者已选择的权限体验；
- 不改变 tmux window/pane 几何，不强制 500 列，不重排真实客户端；
- 保留动物停止按钮、Raw 后备和 Live from tmux；
- 网页输入继续使用现有 paste/confirm/idempotency 状态机，不改成脆弱的文本队列猜测；
- pending follow-up queue 在正式协议缺失时仍报告 unsupported。

### 3.3 UI、内容与隐私

- 完整 Markdown/GFM、KaTeX、Shiki、内部引用卡片、复制原始 Markdown/TeX 不回归；
- 历史分页、全问题导航、Archive/Restore、`/rename` 实时标题不回归；
- composer focus/blur 几何、移动 document scroll、Edge 地址栏行为、PWA/Fullscreen 不回归；
- Changes 继续只读、workspace scoped、限时限长、禁用外部 diff/textconv；
- diagnostics/attention/control audit 不写 prompt、answer、标题、路径、原始 ID、Token 或 Cookie；
- 公开仓库不得出现真实域名、邮箱、账号、Token、Cookie、会话正文、私有绝对路径或
  Cloudflare 资源 ID。

## 4. 目标架构

### 4.1 Owner 后端

目标职责边界：

```text
owner_context.py
  configuration, paths, locks, bounded shared state

tmux_runtime.py
  session discovery, profiles, capture, geometry, safe key/paste primitives

codex_app_server.py
  process lifecycle, JSON-RPC, account/rate-limit and archive operations

codex_history.py
  SQLite/rollout discovery, transcript parsing, paging and caches

delivery.py
  client-message idempotency, receipts, paste/submit confirmation and recovery

attachments.py
  upload parsing, MIME/suffix/size boundaries and inbox paths

owner_http.py
  route dispatch, auth boundary, response helpers, SSE adapter

server.py
  composition root and compatibility-free executable entrypoint
```

拆分原则：

- 先引入显式 Context/Service 参数，后移动函数；
- 不把模块级可变状态简单移动到另一个 `globals.py`；
- subprocess/tmux argv 必须继续固定或经过现有校验；
- 每个新模块先有独立测试，再从 `server.py` 删除旧实现；
- 不通过循环 import 或运行时 monkey patch 维持兼容。

### 4.2 Owner 前端

目标原生模块：

```text
owner/api.js
owner/session-state.js
owner/history-controller.js
owner/capture-controller.js
owner/composer-delivery.js
owner/attachments.js
owner/changes-panel.js
owner/panels.js
app.js                    composition and event wiring only
```

要求：

- 使用浏览器原生 ES modules；
- 以 factory/controller 显式注入 DOM、fetch、storage 和 timers；
- 不让模块自行读取未声明的全局变量；
- 保留现有 Markdown/selection/scroll 模块及 DOM 稳定策略；
- `app.js` 最终只保留组合、跨模块事件和启动顺序，不以行数配额代替职责验收。

### 4.3 Gateway 后端

目标职责边界：

```text
gateway_config.py
  private config loading, users, route policy and bounded settings

gateway_auth.py
  signed cookie, login limiter, CSRF, epoch revoke

control_audit.py
  body-free HMAC target and bounded append/read

bridge_packages.py
  package lifecycle, attachment storage and cleanup

owner_client.py
  fixed-header Owner requests, upload, streaming proxy policy

workbench.py
  active/history aggregation, filtering and privacy-safe payloads

legacy_http.py             development comparison only, removed before release
asgi_app.py
  Starlette route adapters and middleware

run-gateway.py / script
  Uvicorn composition and process entrypoint
```

Starlette/Uvicorn 只负责 HTTP/ASGI，不重新实现业务状态。阻塞的 bcrypt、文件、SQLite、tmux
或 Owner HTTP 工作必须通过受控线程执行，不能阻塞事件循环。

### 4.4 Gateway 前端

先把现有 `workbench.js` 拆为可测试模块：

```text
gateway/api.js
gateway/history.js
gateway/attention.js
gateway/directory-picker.js
gateway/packages.js
gateway/session-model.js
gateway/main.js
```

Preact 试点仅覆盖 Gateway 登录后的主页组件树：Session cards、History、Attention、目录选择和
文件包。登录页、Owner 页面、Markdown transcript 不进入试点。

## 5. 依赖决策门槛

每个新增依赖必须记录固定版本、许可证、生产/dev 分类、transitive dependencies、构建字节、
退出方案和安全验证。

### 5.1 计划采用

- `starlette`：Gateway runtime；路由、middleware、cookies、static/streaming response；
- `uvicorn`：Gateway runtime；ASGI HTTP server；
- `eslint`：development-only；先启用高置信控制流、未使用绑定和 browser/module globals；
- Ruff 继续使用现有版本并逐步加入 `B`，不新增 Python lint package。

### 5.2 条件采用

- `preact`：只在 Gateway pilot 达到第 10 节量化门槛时进入 production bundle；
- TypeScript：本版本不作为 Preact 前置条件；只有 `checkJs` 试验能在不制造大规模迁移债务
  时才另立阶段；
- ShellCheck/actionlint：若 CI 可使用固定版本且不引入平台失真，可作为后续 dev gate，不阻塞
  HTTP 迁移。

### 5.3 明确不采用

- uv；
- FastAPI/Pydantic：当前没有 OpenAPI 产品需求，Starlette 足够；
- Lit：当前是页面组件树，不是 Custom Elements 产品；
- Node.js、Go、Rust 后端重写；
- Floating UI：现有定位函数仍小于引入成本；
- Python Web Push：本版本继续 page-open notification。

## 6. 阶段 A：合同冻结与迁移夹具

在移动代码前记录机器可读合同：

1. 所有 Gateway 路由、方法、状态码、Content-Type、Cache-Control；
2. login/logout/password/revoke 的 Cookie 属性和重定向；
3. CSRF 成功、缺失、错误和过期登录；
4. Owner proxy 的路径、查询、多值头、内部头过滤、404/401/403/502/504；
5. SSE 首头、事件字节、心跳、客户端取消和 upstream disconnect；
6. attachment multipart、最大 body、无 Content-Length、异常 MIME/filename；
7. Gateway workbench/history/package/start/resume/archive payload；
8. CSP、HSTS、nosniff、frame/referrer/permissions headers；
9. 所有错误必须为 JSON 或预期 HTML，不返回 Python traceback/路径；
10. 迁移前每个真实 tmux geometry 快照。

建立 `legacy_gateway_fixture` 和 `asgi_gateway_fixture` 共享测试。合同比较必须规范化时间、nonce、
Cookie 签名和 HMAC alias，但不能宽松忽略状态码、头名、Cookie flags 或 payload 字段。

## 7. 阶段 B：质量门禁

1. 固定 ESLint，记录依赖树与许可证；
2. 先启用不会触发风格风暴的规则：duplicate、unreachable、unsafe-finally、valid-typeof、
   unused bindings；
3. 修复 3 处已知 JavaScript 死代码，不使用 blanket disable；
4. 为 3 个 `B905` 明确选择 `strict=True` 或带注释的有意截断，不全局忽略；
5. Ruff `E9/F/B`、ESLint、Prettier、Node syntax 纳入 `scripts/check-source.sh`；
6. CI 使用相同 lockfile 和命令。

## 8. 阶段 C：Owner 模块化

执行顺序：

1. 提取最纯的 attachment/path 与 runtime diagnostics；
2. 建立 tmux command runner 与 profile/session service；
3. 提取 Codex history/rollout/state DB；
4. 将可靠发送状态机放入显式 `DeliveryService`，保持 per-session/per-message lock；
5. 将 Handler 缩为 route adapter；
6. 每一步运行 Owner unit + real tmux fixture + send matrix；
7. 最后删除旧函数和临时 re-export。

Owner 前端顺序：Changes panel → attachment controller → history controller → capture controller →
composer delivery。Markdown render/selection/live-scroll 最后评估，不为了模块数量移动稳定核心。

## 9. 阶段 D：Gateway 业务拆分和 ASGI 双栈

1. 先把 `GatewayConfig` 的 auth/audit/package 职责变成独立 service；
2. 建立 `OwnerClient`，统一普通 JSON、multipart 与 streaming 三种请求；
3. legacy Handler 只调用 service，不再拥有业务实现；
4. 实现 Starlette app factory 和 Uvicorn 启动器；
5. 在隔离端口同时启动 legacy 与 ASGI，使用相同匿名 fixture/private config 副本；
6. 对所有冻结合同做 normalized response diff；
7. 对 SSE 做逐事件而非整响应比较；
8. 对上传做 hash/size/MIME/filename 比较；
9. 对 slow/upstream reset/client cancel 做 timeout 与资源清理比较；
10. 合同、浏览器、部署全绿后切换 user service；
11. 观察运行日志和公网入口；
12. 发布前删除 legacy HTTP server 和双栈开关。

## 10. 阶段 E：Preact 试点采用门槛

试点必须本地 esbuild bundle、无 CDN，并满足全部条件：

- 迁移范围内不再使用手写 `syncChildren` 或 card `innerHTML` reconciliation；
- Session/History/Attention/Directory/Package 状态由显式 component props/state 驱动；
- 迁移范围源代码至少减少 10%，或明确删除两类已知 DOM/state 缺陷；
- 新增压缩传输体积不超过 12 KiB gzip；
- production bundle 附 Preact 及 transitive notice、版本和 SHA-256；
- 首屏、历史滚动、拖放、触摸、设置 sheet、主题和安装提示无回归；
- 390x844 Edge 与 1440x900 Chrome visual/interaction tests 全绿；
- CSP 继续只允许本地 self asset；
- 失败时删除 Preact pilot 和生成资产，不同时保留 vanilla/Preact 两套页面。

## 12. 发布验收

只有同时满足以下条件才发布 v1.4.0：

1. Starlette/Uvicorn 是唯一发布 Gateway HTTP 实现；
2. legacy `http.server` Gateway 已删除，Owner loopback HTTP 是否迁移不作为本版本要求；
3. 新模块没有循环 import、隐式全局状态袋或未测试兼容层；
4. Preact 已通过采用门槛，或已完整撤回且 vanilla modules 通过；
5. 所有 source、contract、browser、deployment、public、privacy tests 全绿；
6. 真实 Owner/Gateway 服务运行新代码且现有 tmux geometry 未改变；
7. 依赖 ledger、README、architecture、security、runbook、release notes 与计划证据同步；
8. `main` 远程 CI 通过；
9. annotated `v1.4.0` tag 指向通过 CI 的干净 main；
10. Release workflow 发布 source-only release。

## 13. 回滚

- 每一阶段一个行为闭合提交，不把质量门禁、Owner 拆分、ASGI 切换和 Preact 混在一个提交；
- 本机切换前记录 Gateway service、端口、PID、Python、健康和 tmux geometry；
- ASGI 切换失败时，开发期间可恢复上一行为闭合提交；
- v1.4.0 发布后的正式回滚为检出 `v1.3.0`、安装该版本 requirements、重启 Owner/Gateway；
- 不删除或迁移 Codex rollout、SQLite history、send receipts、inbox、Gateway auth config、
  Cloudflare Access 或 tmux sessions；
- 外部 HSTS、GitHub Issues/Discussions/Dependabot 配置不依赖 v1.4.0 代码，回滚代码时保留。
