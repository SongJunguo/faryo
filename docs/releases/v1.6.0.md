# Faryo 1.6.0

Faryo 1.6.0 replaces raw browser-to-TUI menu controls with versioned structured
interactions and moves the Owner's dynamic interaction shell to a focused local
Preact + TypeScript + Vite bundle.

## Structured Codex interaction

- `/model`, model/reasoning levels, `/usage`, permissions, approvals,
  resume-directory, workspace trust and generic blocking menus share one
  `InteractionService` and Codex TUI adapter.
- Opaque interaction/option IDs, generation fences, per-session locks and
  idempotent receipts reject stale tabs without sending keys twice.
- Refresh and SSE reconnect rebuild pending state from the real TUI. Unknown
  menus retain explicit Previous, Next, Choose highlighted and Cancel actions.
- The current 46-command fallback is versioned for Codex 0.148.0; a private
  read-only inventory detects future drift and marks new commands unclassified.

## Owner Web UI and session recovery

- Preact owns composer markup, command-palette state/keyboard navigation,
  interaction sheets and Context/Week/Model/Goal/Git status. Markdown/TeX,
  complete history, Raw/Chat and Live tmux remain isolated rendering surfaces.
- Historical top-level CLI/VS Code rows with legacy `thread_source=NULL` are
  searchable and resumable; subagent/guardian rows remain hidden.
- Missing resume cwd is selected before tmux creation with a signed path token.
  Active thread-ID URLs resolve to their real tmux and canonicalize the URL.
- Goal details are fetched only on click, use no-store, clear on close and never
  enter status, diagnostics, logs, history, audit or browser storage.

## Fast launch and queued Send now

- Start/Resume returns an accepted Starting receipt immediately after managed
  tmux creation. A pane-PID-fenced, single-flight monitor completes readiness in
  the background and is reconstructed after Owner restart.
- The page shows Starting instead of `session unknown`, then transitions to
  Waiting, a structured startup interaction, or a bounded Exited error.
- When Codex explicitly advertises `press esc to interrupt and send immediately`,
  the squirrel displays an ESC badge. Phone tap and unobstructed desktop Escape
  share one `queuedFollowupExpedited` receipt. Queue list/edit/reorder remains
  deliberately unsupported.

## Deployment and cache safety

- Mutable Owner assets use the rendered Faryo release version as their cache
  key; missing/rejected assets are `no-store`. Normal reload/new tab is enough.
- Gateway's source gate verifies every Owner HTML script against its authenticated
  static allowlist.
- Owner systemd uses `KillMode=process`; update gates compare session name, pane
  PID and geometry so a same-name restarted Codex cannot masquerade as preserved.
- The installed `faryo` launcher uses Python isolated mode and verifies its exact
  package version, so an ambient/stale `PYTHONPATH` cannot import an older Faryo.

## Upgrade

```bash
faryo update --version v1.6.0
```

The update preserves `~/.faryo`, authentication, Codex history, attachments and
existing tmux sessions. It does not modify Cloudflare policy.

## Verification

- Canonical source gate: 176 Owner, 114 Gateway and 55 CLI Python tests plus
  lint, format, TypeScript and reproducible bundle checks.
- Real authenticated 390x844 Gateway `/model`/reload/Cancel and `/usage` pass.
- Real async Start returns in about 51ms and survives an Owner restart without
  changing pane identity; synthetic queued Esc is observed end to end.
- Every pre-existing deployed tmux pane retains its PID and 145x44 geometry.
