# Faryo 1.5.2

Faryo 1.5.2 removes stale server-rendered loading placeholders after Preact
takes ownership of Gateway lists and clears a completed Goal indicator when a
new user turn begins without a new Goal.

## Launcher and list ownership

The Gateway HTML intentionally contains useful loading placeholders before the
first workbench request completes. Preact previously rendered its list beside
those unowned nodes instead of removing them, so a successful `Start Codex`
card could still be followed by `Loading launchers…`. Empty Files, Active, and
History placeholders could be duplicated for the same reason.

Each maintained list now:

1. keeps its server placeholder until the first real model or error arrives;
2. clears unowned children exactly once when Preact claims the container;
3. uses normal keyed reconciliation for every later refresh;
4. preserves focused cards and component-local transient state.

The browser regression requires one launcher child for one launcher card, no
remaining `Loading …` empty state, and at most one Files empty state.

## Completed Goal clear semantics

Faryo receives Goal metadata from privacy-safe rollout events and tool results;
Codex App Server's current thread object does not expose live Goal state. A Goal
clear performed outside the rollout may therefore have no explicit
`thread_goal_updated(goal=null)` record.

Faryo now treats a completed Goal as belonging to the turn that completed it:

- `Goal Done` remains visible after completion;
- a newer real user turn without a newer Goal hides the completed pill and
  reports `No goal` in Details;
- active, blocked, paused, and usage-limited Goals remain visible;
- explicit Goal clear and subsequent Goal events continue to take precedence.

Only status and bounded usage/timing metadata are processed. Goal objective and
thread identity remain outside the Owner API and browser.

## Upgrade

```bash
faryo update --version v1.5.2
```

The update does not change `~/.faryo`, Codex history, attachments, login state,
tmux sessions, or Cloudflare configuration.

## Verification

- Canonical source gate: 131 Owner, 112 Gateway, and 51 CLI Python tests plus
  maintained Node/browser modules and reproducible UI bundles.
- Real mobile Gateway verifies one `Start Codex` card, no stale launcher/list
  loading placeholder, and stable keyed card identity across refresh.
- A real cleared completed Goal returns no pill and `No goal` after the next
  user turn.
- Owner/Gateway stay healthy and every existing tmux session keeps its geometry.
