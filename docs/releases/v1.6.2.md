# Faryo 1.6.2

Faryo 1.6.2 adds explicit working-directory selection when resuming a saved
Codex conversation, without slowing down the existing default resume path.

## Choose folder and resume

- Inactive resumable Codex cards now expose `Choose folder` beside `Archive`.
- Clicking the card body remains the fast path and resumes with the conversation's
  recorded working directory.
- `Choose folder` opens the maintained authenticated directory browser. The
  selected canonical path and Owner-signed selection token are sent with the
  first resume request, so Faryo does not first create a session in the old cwd.
- Active sessions never expose the action. Archived threads must be restored
  before either resume path is available, and the running-session limit is
  applied consistently.

The directory browser retains breadcrumbs, parent navigation, current-page
search, the remembered Hidden toggle, complete child-folder lists, root/symlink
containment and Owner revalidation.

## Upgrade

```bash
faryo update --version v1.6.2
```

This update preserves authentication, history, attachments and existing
tmux/Codex processes.

## Verification

- Component tests cover resumable, active, archived and limit-reached action
  ownership.
- Anonymous browser routes verify that a normal card click sends no cwd, while
  explicit folder selection sends exactly one resume request with the selected
  cwd and its signed token.
- The canonical source gate covers Python 3.10/3.13, formatting, lint,
  TypeScript, reproducible local bundles and the existing Owner/Gateway/CLI
  reliability contracts.
