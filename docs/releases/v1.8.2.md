# Faryo 1.8.2

Faryo 1.8.2 resolves the Android Edge composer gap that remained in the v1.8.0
and v1.8.1 source candidates.

## Root cause

A privacy-safe wireless ADB/CDP A/B measured the same real Edge page with the
same keyboard in both platform modes:

- VirtualKeyboard overlay kept `innerHeight` at 652 CSS px, exposed a 357 px
  keyboard inset and made the fourth grid row stop the footer at 295 px;
- native `interactive-widget=resizes-content` reduced `innerHeight` to 346 px,
  and the three-row app shell placed the footer at the same 346 px boundary.

The second state also removed the visible blank reserve in a device screenshot.
The failure was therefore not stale assets, a fixed-footer offset or a missing
keyboard event. The overlay coordinates exposed by this Edge/browser-toolbar
combination were not a usable page-layout contract.

## Changes

- Uses `interactive-widget=resizes-content` as the single production keyboard
  contract.
- Explicitly sets `navigator.virtualKeyboard.overlaysContent=false` when the API
  is present, including when an older loaded page had enabled it.
- Deletes the CSS keyboard-inset variable, fourth grid row, geometry-change
  listener and overlay lifecycle branch.
- Keeps the composer as a normal app-shell row and `main` as the only
  conversation scrollport.
- Adds a reusable Android Edge CDP measurement tool that reports only viewport,
  inset and known-element geometry; it never prints a URL, token, session title
  or conversation text.

## Validation gate

The source controller and real Chromium layout fixture cover an API-present
browser beginning in overlay mode, an API-absent browser, resize coalescing,
controller cleanup and a 720-to-480 px viewport contraction. The release remains
a source candidate until the versioned local deployment passes ordinary reload,
keyboard open/close, portrait/landscape, foreground recovery, full source and
browser suites, reliable sending, authentication boundaries and unchanged tmux
geometry.
