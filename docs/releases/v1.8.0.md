# Faryo 1.8.0

Faryo 1.8.0 replaces device-specific mobile keyboard positioning with a single
conversation app shell whose composer remains in normal layout flow.

## Changes

- Uses one `100dvh` grid and one bounded conversation scrollport across direct
  Owner, Gateway, desktop, PWA and Fullscreen views.
- Feature-detects the Chromium VirtualKeyboard API and consumes
  `env(keyboard-inset-height)` as a grid row; unsupported browsers use
  `interactive-widget=resizes-content` without pixel or device thresholds.
- Deletes the document-scroll adapter, fixed mobile footer, VisualViewport dock,
  duplicate history reserve and their retired tests.
- Prevents a buffered event from a closed SSE connection from updating the
  current conversation.
- Keeps sticky controls out of browser scroll anchoring and makes rapid question
  jumps immediate, so an older smooth-scroll frame cannot clip the new target.

## Validation

- Canonical source gate: 199 Owner, 117 Gateway and 57 unified-CLI Python tests,
  plus Ruff, Prettier, TypeScript, Node controller tests and reproducible local
  browser bundles.
- Anonymous 40-turn Markdown/KaTeX history retains 40 question markers while
  rendering only five rich bodies initially; lazy paging, Raw to Chat, resize
  and PWA/Fullscreen checks pass at 390x844.
- Reliable-send matrix passes 20 messages, clipboard attachment, network and
  background recovery, ambiguous ACK de-duplication and failed-draft retention.
- Protected resources, cross-session isolation, Live tmux copy/selection and
  read-only workspace review pass without changing temporary tmux geometry.

## Candidate status

This source candidate remains behind the Android Edge real-keyboard acceptance
gate. It must not replace the current public release until that gate, ordinary
reload and live service health all pass.
