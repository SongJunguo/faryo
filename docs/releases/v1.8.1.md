# Faryo 1.8.1

Faryo 1.8.1 fixes the duplicate mobile keyboard reserve exposed by the first
Android Edge acceptance screenshot for v1.8.0.

## Changes

- Keeps the feature-detected VirtualKeyboard imperative opt-in and viewport
  declaration consistent: successful `overlaysContent=true` now pairs with
  `interactive-widget=overlays-content`.
- Retains `interactive-widget=resizes-content` unchanged when the API is absent.
- Restores the original viewport declaration atomically when the API refuses the
  overlay request, initialization fails or the controller is destroyed.
- Uses no keyboard-height threshold, device sniffing, footer translation or
  VisualViewport coordinate conversion.

The CSS Viewport specification says `VirtualKeyboard.overlaysContent=true`
shadows `interactive-widget`; the explicit matching declaration is a defensive
compatibility measure for the contradictory Android Edge behavior observed in
the real acceptance gate: <https://drafts.csswg.org/css-viewport/#interactive-widget-section>.

## Validation

- Node fixtures cover viewport declaration replacement, overlay refusal,
  geometry changes and exact restoration.
- Real Chrome and Microsoft Edge DOM fixtures verify overlay mode, the
  `overlays-content` declaration, CSS inset grid geometry and controller cleanup.
- The full source, history, reliable-send, authentication and portrait/landscape
  PWA/Fullscreen gates pass. The versioned local deployment reports 22/22 health;
  ordinary reload retains the v1.8.1 asset key and `overlays-content` contract,
  while all seven pre-existing tmux windows keep their geometry and pane identity.

## Candidate status

This candidate remains behind a second Android Edge real-keyboard screenshot.
It must not replace the public release until the composer sits directly above
the keyboard in portrait and landscape without a duplicated blank reserve.
