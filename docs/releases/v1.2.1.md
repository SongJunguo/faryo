# Faryo 1.2.1

Faryo 1.2.1 makes Session History safer to organize and removes the unused
Project Orchestration surface from the maintained Codex workbench.

## Highlights

- Resumable history cards now offer `Archive`; archived cards offer `Restore`.
  Faryo delegates both operations to Codex App Server's official
  `thread/archive` and `thread/unarchive` lifecycle RPC.
- Archive is reversible and protected by login, route authorization, CSRF,
  workspace scope, active-thread conflict checks and body-free HMAC audit.
- Faryo never directly modifies Codex SQLite/rollout state and deliberately
  exposes no hard-delete endpoint or UI.
- `/` is now the single maintained Gateway home. The ambiguous `/projects`
  Project Orchestration page and its unreachable controller, workorder and
  downlink backend have been removed; the old route returns `404`.
- Generic Files-to-session handoff, Start/Resume/Close, structured history,
  Markdown/TeX, reliable send and tmux controls remain intact.
- Re-running the Owner initializer removes retired project-workbench keys while
  preserving the Owner token and explicit start-directory roots.
- The cleanup removes roughly 4,000 net lines from the maintained runtime path.

## Upgrade

Update the source checkout and isolated environment, then run the canonical
check:

```bash
git fetch origin --tags
git switch main
git pull --ff-only origin main
conda activate faryo
python -m pip install -r apps/gateway/requirements.txt
scripts/check-source.sh
```

Migrate the private Owner environment and restart both services:

```bash
./apps/owner/scripts/init-owner-env.sh
./apps/owner/scripts/start-web-owner.sh
systemctl --user restart faryo-gateway.service
```

The initializer preserves the existing Owner token. Back up private runtime
configuration according to the operator's normal deployment policy before an
upgrade.

## Compatibility changes

- `/projects` and Project Orchestration APIs are no longer routable.
- Retired `FARYO_PROJECT_WORKBENCH_*` Owner keys are removed during
  initialization. An old allowed-roots value is migrated only when no explicit
  `FARYO_START_DIRECTORY_ROOTS` is already configured.
- Private Project runtime directories are not deleted by this release.
- This remains a source-only Ubuntu/Linux + Codex release; no binary package is
  published.

## Verification

- Canonical source check: 82 Owner and 62 Gateway Python tests plus maintained
  JavaScript/source contracts.
- Real isolated Codex App Server Current→Archived→Current round trip through
  Owner, with unchanged rollout SHA-256 and the real Codex home untouched.
- 390x844 Chrome and 1440x900 Edge workbench checks for Archive/Restore card
  eligibility, reversible confirmation, absent Delete, history search/pages,
  Files-to-session, `/` branding and no horizontal overflow.
- Authenticated `/projects` returns `404`; both loopback services remain healthy.
- Every pre-existing Codex tmux window retains its original dimensions.

## Rollback

Check out `v1.2.0`, reinstall its declared dependencies and restart Owner and
Gateway. Source rollback does not delete private runtime state, Codex rollout
history or tmux sessions. Threads archived through Codex remain restorable by
Codex even if the older Faryo UI has no Restore button.
