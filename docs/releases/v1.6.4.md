# Faryo 1.6.4

Faryo 1.6.4 adds a reliable per-conversation Default/Fast speed control.

## Session-scoped speed

- The Owner header shows `Default` or `Fast` beside the current model.
- Clicking it submits Codex's exact `/fast` local command once through the
  structured command service; Faryo does not simulate repeated Enter keys.
- Only the selected Codex/tmux conversation changes. Other browser tabs and
  sessions retain their own speed, and Faryo does not edit the global Codex
  default.
- Existing unsent browser text is preserved across the toggle.
- The control is disabled while Codex is running, starting, exited, or waiting
  for another structured interaction.

Faryo now parses `gpt-5.6-sol max fast` into three independent fields: model,
reasoning effort, and session service tier. A missing trailing `fast` marker is
an explicit Default state rather than a fallback to another conversation's or
the global configuration's value.

## Upgrade

```bash
faryo update --version v1.6.4
```

## Verification

- Python regressions cover Fast and Default TUI rows, `max` effort, a model slug
  containing the word fast, and the missing-model fallback.
- Preact browser tests cover mobile/desktop layout, accessibility state,
  in-flight disabling and the active visual state.
- A privacy-safe two-tab browser fixture requires one session to switch to Fast
  while the other remains Default, preserves both drafts, verifies the exact
  `/fast` request target, and restores the original state.
- The canonical source gate covers Python 3.10/3.13, formatting, lint,
  TypeScript, reproducible local bundles and existing Owner/Gateway/CLI
  reliability contracts.
