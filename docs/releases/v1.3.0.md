# Faryo 1.3.0

Faryo 1.3.0 uses selected mature libraries to reduce maintenance cost and adds
read-only workspace review, redacted diagnostics and body-free attention.

## Highlights

- Locked Playwright Core and Ruff development tooling now runs in canonical CI.
  The first two browser-test migrations produce a net source reduction, and the
  initial Ruff pass removed stale imports plus an unused tmux capture.
- Source and release workflows use the current Node 24-based v7 GitHub Actions,
  removing the deprecated Node 20 action-runtime warning.
- Browser regression scripts and the live Codex command inventory now share the
  same Python, Node and Codex runtime resolver as CI, while retaining their
  existing per-test overrides.
- Gateway portal CSS and JavaScript are versioned external assets instead of
  embedded Python strings. Allowed route labels use a nonce-protected JSON
  bootstrap; CSP and login/CSRF boundaries are unchanged.
- Session Details includes a workspace-scoped, strictly read-only Changes panel.
  Phone uses line-by-line diff, desktop can use split view, and large output is
  bounded and explicitly marked.
- diff2html and DOMPurify are reproducibly bundled as lazy local assets. The
  bundle includes licence/hash provenance and never requires a CDN.
- Owner exposes versioned capability metadata and downloadable redacted
  diagnostics containing feature/protocol flags and counts only.
- Gateway includes an in-memory Attention center for Waiting/Exited sessions.
  Optional page-open browser notifications require a direct permission gesture
  and use only the generic body `A session completed or needs input.`
- Pending follow-up editing is deliberately not claimed: official Codex App
  Server and the local generated schema expose `turn/steer`, but no queue
  list/edit/reorder/cancel RPC for a TUI-owned turn.

## Dependency decisions

- Added development-only: Playwright Core 1.62.1, Ruff 0.16.3, esbuild 0.28.2
  and Prettier 3.9.6.
- Added lazy local runtime bundle: diff2html 3.4.56 and DOMPurify 3.4.14.
- Floating UI was evaluated but rejected because the current tested placement
  function is much smaller than the added runtime bundle.
- Preact/Lit, FastAPI/Pydantic and background Web Push remain conditional future
  work rather than v1.3 dependencies.

See the repository dependency ledger for licences, sizes, hashes, measured
benefit and removal paths.

## Security boundaries

- Git root must remain within the configured workspace scope; symlink escape is
  rejected.
- Git commands use fixed argv with external diff, textconv, pager and color
  disabled; there is no stage, discard, commit, checkout or apply endpoint.
- Diff filenames are inserted with `textContent`; generated HTML passes through
  DOMPurify and browser XSS regression.
- Diagnostics and attention contain no credentials, host/user identity, raw
  target ID, path, title, prompt or answer.
- Notifications are page-open only; v1.3 stores no VAPID private key or push
  subscription database.

## Upgrade

```bash
git fetch origin --tags
git switch main
git pull --ff-only origin main
conda activate faryo
python -m pip install -r requirements-dev.txt
npm ci --ignore-scripts
scripts/check-source.sh
./apps/owner/scripts/start-web-owner.sh
systemctl --user restart faryo-gateway.service
```

The runtime itself still imports only the Gateway requirements; development
packages are used for builds and tests. Refresh existing browser tabs once for
the versioned Gateway/Owner assets.

  context cleanup.
- 390x844 and 1440x900 workspace Changes matrix: lazy assets, line/split diff,

  filename and bounded-output tests.

- Existing formula, history, reliable delivery, Live, PWA/Fullscreen and mobile
  document-scroll matrices pass with unchanged agent tmux geometry.
- Live Codex 0.148.0 command inventory matches all 46 visible slash commands.

## Rollback

Check out `v1.2.2`, install that revision's dependencies and restart Owner and
Gateway. Changes, capability, diagnostics and attention are read-only/browser
features, so rollback requires no private-state migration and does not alter
Codex history or tmux sessions.
