# Faryo 1.0.0

Faryo 1.0.0 is the first open-source release of the unified Faryo repository.

## Positioning

Faryo is a lightweight mobile workbench for long-running terminal AI sessions.
It keeps phone and desktop control attached to the same tmux-backed Codex,
Claude, or shell session instead of creating isolated remote pages.

## Product Definition

- Mobile workbench for terminal AI sessions.
- Continuity layer over `tmux`.
- Gateway for public access, routing, auth, and handoff policy.
- Owner endpoint for local tmux capture, send, interrupt, approval, and
  attachment handling.
- Cross-device session history surface for phone and desktop.
- Handoff package inbox for prompts, files, screenshots, notes, and intent.
- Multi-endpoint cockpit for HP, PC, and cloud machines.
- Thin PWA interface, not a remote desktop stack.
- Self-hosted endpoint runtime package.
- Small open-source tool, not a hosted IDE or chat platform.

## Compatibility Notes

The most refined path in this release is Linux endpoint runtime plus tmux,
Codex CLI, and Chrome/Android Chrome PWA. That path has received the most work
around mobile viewport behavior, compact output, command input, attachment
handling, session switching, and Codex history convergence.

macOS Owner packaging, iOS Safari, Claude Code, and generic shell TUIs are
supported surfaces, but they have not received the same level of tuning. Expect
future optimization around browser background behavior, paste/input edges,
compact rendering, and agent-specific session mapping.

Codex and Claude use separate session convergence rules. Codex convergence reads
the local Codex session database, filters internal/subagent branches, maps the
active tmux process to the current Codex thread, and resumes with
`codex resume`. Claude convergence reads Claude JSONL history, tracks managed
tmux sessions with Faryo metadata, and resumes through Claude session IDs.

## Highlights

- Unified Gateway and Owner source tree under the Faryo identity.
- Gateway workbench for login, route health, session selection, and handoff
  packages.
- Owner endpoint for loopback-only tmux capture, send, interrupt, approval,
  attachment upload, and Codex/Claude session resume.
- Mobile PWA with compact and raw views, attachment handling, session switching,
  and same-session history continuity.
- Endpoint packages for Debian-style systems and macOS.
- Owner `/api/status` includes `releaseVersion` so endpoint upgrades can be
  accepted through the authenticated route.
- Public release hygiene for docs, license, security notes, examples, and
  private-path cleanup.
- UI interaction documentation for the Gateway workbench, Owner session view,
  compact/raw output modes, handoff packages, attachments, and mobile controls.

## Security

- Owner remains loopback-first and token protected.
- Gateway injects Owner tokens server-side and strips user-supplied owner
  control headers.
- Bridge attachment URL intake blocks hostnames that resolve to private,
  loopback, link-local, multicast, reserved, or unspecified addresses.

## Packaging

`scripts/package-client.sh release` builds:

- `dist/faryo_1.0.0_all.deb`
- `dist/faryo_1.0.0_macos.tar.gz`
- `dist/SHA256SUMS`

The client package intentionally excludes Gateway server files.
