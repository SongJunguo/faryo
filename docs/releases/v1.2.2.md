# Faryo 1.2.2

Faryo 1.2.2 adds a deliberate mobile immersive-reading path and records a
data-backed architecture and similar-project roadmap.

## Highlights

- Every maintained session page now references Gateway's root-scoped PWA
  manifest. Installing Faryo with its existing `display: standalone` mode opens
  the workbench without the ordinary browser URL bar.
- Narrow normal-browser sessions reached through Gateway now use a tested
  document scroll surface. This gives mobile Edge/Chromium real top-level scroll
  input so their native address/action bars can retract; direct Owner, desktop
  and installed PWA views keep the bounded conversation scroller.
- A direct tap on the session header or Details enters the Fullscreen API mode
  and requests hidden navigation UI. The control becomes a labelled `Exit`;
  folding the header reveals a separate `Exit full screen` pill.
- Browser Back, system gestures and Esc remain valid exits. External exits are
  reconciled through `fullscreenchange`, and full-screen state is never restored
  automatically after reload or session navigation.
- Unsupported or rejected fullscreen requests leave the page usable and point
  to the standalone PWA install path.
- Permissions Policy now explicitly allows fullscreen only for the same origin;
  camera, microphone and geolocation remain disabled.
- The immersive controller is an independent dependency-free browser module
  with Node state-machine tests and a trusted-click Chrome DevTools smoke test.
- The repository now includes a measured architecture audit and comparison with
  Happy, Happier, Harness Remote, Tether and Codex Remote, including a staged
  dependency and refactor roadmap.
- The concise root `AGENTS.md` records one principle: lightweight does not mean
  dependency-free; focused mature libraries are welcome when they reduce real
  complexity and remain pinned, local and tested.

## Selective mobile scrolling

Mobile browsers still control their own dynamic address and action bars; no page
can promise when a particular browser retracts them. Faryo now supplies the
missing prerequisite on narrow Gateway tabs: genuine document-root scrolling.
The adapter preserves structured-history anchors, live-follow, question
navigation and the fixed composer without synthetic one-pixel scrolling. Use
temporary full screen or the installed standalone PWA when browser chrome must
be absent rather than merely eligible to auto-hide.

## Upgrade

```bash
git fetch origin --tags
git switch main
git pull --ff-only origin main
conda activate faryo
python -m pip install -r apps/gateway/requirements.txt
scripts/check-source.sh
./apps/owner/scripts/start-web-owner.sh
systemctl --user restart faryo-gateway.service
```

Refresh an existing browser tab once so the versioned Owner stylesheet and
scripts reload. To install the PWA, use `Install app` from Gateway Home when the
browser offers it.

## Verification

- Canonical source check: 82 Owner and 63 Gateway Python tests plus all
  maintained browser-module and source contracts.
- Fullscreen unit matrix: supported/unsupported, enter/exit, external exit,
  rejection fallback and event cleanup.
- Trusted-click full-screen entry and exit in 390x844 Edge/Chrome and 1440x900
  Edge, through both header and Details, including the folded-header exit path.
- Trusted-touch 390x844 Edge document scrolling through the real Gateway: root
  scroll changes, inner-main scroll stays zero and the fixed composer stays visible.
- Mobile/desktop Owner layout, 40-turn lazy history, protected resources,
  Markdown/GFM/KaTeX/Shiki, Raw→Chat, question navigation and copy regressions.
- Twenty-message reliable-delivery matrix with clipboard image, offline and
  background recovery, ambiguous retry and failed-draft preservation.
- Two-session delayed-response isolation and 390x844/1440x900 Live selection,
  scroll and copy matrices.
- Existing tmux window dimensions unchanged across every browser test.

## Compatibility and dependencies

- No new production framework, CDN or native app runtime is introduced.
- The PWA manifest remains `standalone`, not permanently `fullscreen`, so users
  retain a predictable app window and explicit navigation.
- Normal browser tabs continue to work when Fullscreen API is unavailable.
- This remains a source-only Ubuntu/Linux + Codex release.

## Rollback

Check out `v1.2.1`, reinstall its declared dependencies and restart Owner and
Gateway. Fullscreen state is browser-only, so rollback requires no runtime-data
migration and does not alter Codex history or tmux sessions.
