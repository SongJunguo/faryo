# Faryo 1.6.3

Faryo 1.6.3 fixes the first page of a newly created Codex conversation.

## Clean empty conversation state

- A successfully read Codex thread with zero turns is now treated as valid
  structured state rather than an unavailable transcript.
- Chat shows `No messages yet. Ask Codex to start this conversation.` before the
  first prompt.
- TUI startup redraws such as `Codex ready` and `Ask Codex to do anything` no
  longer appear as fake conversation history.
- The terminal fallback warning remains available when both the durable rollout
  and Codex App Server genuinely fail.
- After the first submitted prompt, capture naturally advances from an empty
  App Server thread to the durable `codex-jsonl` conversation.

Raw terminal evidence, the transient Live panel, send reliability, structured
interactions and tmux geometry are unchanged.

## Upgrade

```bash
faryo update --version v1.6.3
```

## Verification

- Python regressions distinguish a valid empty thread from a failed structured
  read and retain rollout precedence once a message exists.
- A privacy-safe mobile browser fixture injects an empty structured capture and
  requires the clean empty message, no fallback warning, no terminal startup
  text and no horizontal overflow.
- The canonical source gate covers Python 3.10/3.13, formatting, lint,
  TypeScript, reproducible local bundles and existing Owner/Gateway/CLI
  reliability contracts.
