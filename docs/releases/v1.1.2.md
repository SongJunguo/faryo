# Faryo 1.1.2

Faryo 1.1.2 rebuilds the Claude Code compact-view convergence for the
Claude Code v2 TUI and gives Claude sessions their own status-bar data
path, separate from Codex.

## Highlights

- Claude compact rules are rewritten against the Claude Code v2 output
  format: the v2 logo banner, combined footer chrome, and tip lines are
  stripped; tool summary sentences and numbered file previews collapse
  into the process summary card; adjacent status lines merge into one
  block; the permission mode is shown as a small status line.
- The startup-screen collapse no longer misfires on transcripts that
  mention "Claude Code v" in message content; it requires a real banner
  and otherwise-empty capture.
- Claude session status now reads the model name and context usage from
  the session JSONL (200k window by default, 1M for `[1m]` models); the
  hardcoded model fallback is removed. Codex context usage keeps its
  rollout-based path.
- The header quota meter shows Claude weekly rate limits fetched from the
  Claude Code OAuth usage endpoint: overall weekly on the top bar and the
  model-scoped weekly (for example Fable) on the bottom bar. Codex quota
  rendering is unchanged.
- Claude sessions launched or resumed through Faryo set
  `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1`, keeping the conversation in
  normal tmux scrollback so compact and raw capture windows cover full
  turns again.
- Claude history discovery drops headless-spawned sessions (no `mode`
  event) and sessions whose only user content is local-command wrapper
  text; titles skip command wrapper text.
- The compact view strips the input composer box, and context usage
  treats an input count above the 200k window as evidence of a 1M
  window even when the model name carries no `[1m]` marker.

## Gateway

- The sign-in and password pages can show a filing record in the footer,
  linked to the official filing site, driven by `FARYO_ICP_RECORD` in the
  same `faryo.env` as the other settings. Unset means no footer, so the
  field stays out of deployments that do not need it.
- The Cloud Run VM guard is retired. It hard-reset a Compute Engine
  instance after repeated health failures, which no longer applies once
  Gateway runs elsewhere, and its `/api/guard-health` endpoint had no
  remaining caller. `FARYO_GUARD_TOKEN` stays: a dispatched agent still
  uses it to call back into `/api/faryo/workorder/verify`.
- Route documentation and script defaults drop the retired GCP wording:
  `/gcp/` paths become `/txy/`, the HP route points at
  `FARYO_HP_OWNER_HOST` instead of a loopback port that no longer
  matches, and two scripts stop defaulting to a tunnel unit that does not
  exist.
