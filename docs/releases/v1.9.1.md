# Faryo 1.9.1

Faryo 1.9.1 is the deployment candidate for the App Server streaming work
introduced in 1.9.0.

## Changes since 1.9.0

- Removes the credential-shaped `?token=<private-token>` placeholder from the
  Owner startup journal. The previous text was a fixed redacted literal and did
  not contain the real secret, but a credential-free listen URL is clearer and
  can be checked without false-positive log alerts.
- Updates the real Gateway Start Codex regression to recognize a zero-message
  Web-managed session from its authenticated `backend` and lifecycle state.
  Terminal-managed compatibility still uses the reported Codex model/TUI-ready
  evidence. The test no longer guesses readiness from a model-name prefix that
  App Server does not promise before the first turn.

## Validation

- Canonical source gate: 220 Owner, 118 Gateway and 60 unified-CLI Python tests,
  plus the locked frontend, lint, format and bundle checks.
- An isolated real Codex 0.149.0 run produces a read-only-sandbox approval,
  executes the approved action, emits plan-mode `request_user_input` with two
  choices, accepts the selected answer and carries it into the final response.
- The v1.9.1 installed topology passed 24/24 doctor checks, App Server reported
  ready on its private socket, both HTTP listeners remained loopback-only, the
  public edge challenged unauthenticated requests, and all pre-existing tmux
  pane identities and dimensions stayed unchanged.
- The authenticated Gateway browser passed launcher replacement, three history
  pages, directory selection, Web-managed empty-session readiness and cleanup.

The v1.9.1 reinstall, authenticated ordinary-browser path, public Access
challenge, service-log and tmux-geometry gates pass. The feature branch remains
unmerged until its final Git/privacy audit completes.
