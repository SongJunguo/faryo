# Faryo 1.5.1

Faryo 1.5.1 completes the project's GitHub standalone migration and fixes
working-directory selection after a workspace is renamed or removed.

## Standalone project and discoverability

- The maintained repository is now
  `SongJunguo/faryo-codex-web-ui`, with the display name **Faryo Codex Web UI**.
- GitHub reports `fork=false`; the original `Snailflyer/faryo` baseline remains
  preserved in Git history and as a non-pushable local upstream reference.
- README title, badges, clone/release links, description, and 20 focused topics
  cover Codex CLI Web UI, agent workbench, tmux, mobile/PWA, Markdown/LaTeX/KaTeX,
  and secure remote access without keyword stuffing.
- The README explicitly states that Faryo is an independent community project,
  is not affiliated with or endorsed by OpenAI, and uses Codex only to describe
  compatibility.
- New updater and bootstrap builds use the standalone repository URL. GitHub's
  old repository and Release URLs redirect to the new slug, so the v1.5.0
  updater continues to work.

## Directory picker recovery

The Start Codex directory picker previously tried only the newest Recent path.
If that directory had been renamed or removed, it immediately fell back to the
workspace root even when another valid Recent path existed.

It now:

1. deduplicates Recent candidates in their existing order;
2. tries each candidate until Owner confirms one is available;
3. falls back to the configured root only after every Recent path fails;
4. keeps normal navigation errors explicit after the picker opens.

This makes repository and workspace renames recover naturally without editing
Codex rollout history or private session metadata.

## Upgrade

```bash
faryo update --version v1.5.1
```

The update remains checksum-verified, independently versioned, and
health-gated. It does not migrate `~/.faryo`, Codex history, attachments, tmux
sessions, login state, or Cloudflare configuration.
