# Faryo 1.2.0

Faryo 1.2.0 is the first maintained source-only release of this personal fork.
It focuses on one production path: a self-hosted Ubuntu/Linux workbench that
reads and controls the same tmux-backed Codex CLI session from desktop or mobile.

## Highlights

- Formula-first Compact Chat renders CommonMark/GFM and TeX through a local AST
  pipeline, KaTeX and lazy Shiki assets. It supports tables, cases, matrices,
  wide equations, code highlighting and source-faithful Markdown/TeX copy
  without a runtime CDN.
- Structured Codex history uses bounded initial pages, lazy older-page loading,
  complete question navigation, `/rename` synchronization and safe tmux fallback.
- Browser-to-Codex sends are session-isolated, idempotent across retries and
  ambiguous 502/504 responses, and preserve browser/TUI drafts on failure.
- Gateway separates Active Sessions from 10-record Session History pages and
  adds server-side title, explicit rename, folder, date and archive filtering
  without scanning conversation bodies.
- `Start Codex` uses `faryoN` managed tmux names, real process readiness,
  idempotent launch IDs and a signed, workspace-scoped graphical directory
  picker.
- Session cards expose Starting, Running, Waiting, Exited, Desktop, Resumable
  and Archived from descendant-process/TUI evidence rather than only
  `pane_current_command`.
- Composer images can be pasted from a user-triggered clipboard event with
  accompanying text preserved, compressed previews, removal and the existing
  reliable attachment send path. Faryo never requests background clipboard read.
- Chat and Raw keep independent capture caches. Returning to Chat restores rich
  Markdown/TeX and automatically collapses the separate Live tmux panel.
- Live tmux keeps a bounded 180-line current-turn tail, stable DOM and scroll,
  pauses updates during text selection, then flushes the newest version; a
  dedicated button copies the visible terminal text.
- Contextual terminal controls now read `Codex menu / Previous / Next / Enter
  Choose`, appear only for a detected TUI choice, and auto-hide after Enter.
- Gateway records body-free control metadata in a private mode-600 audit with
  seven-day/5000-row retention and HMAC-pseudonymous targets. Security activity
  is scoped to the signed-in user and routes; prompts, answers, titles, paths,
  raw IDs, credentials and IP history are not audit fields.

## Supported release path

- Ubuntu/Linux workstation
- Python 3.11 or newer; Python 3.13 is validated
- Node.js 20 or newer for source validation; Node.js 24 is validated
- tmux and Codex CLI
- current Chrome or Microsoft Edge
- loopback Owner and Gateway behind an operator-controlled HTTPS identity layer
  when remote access is enabled

This release does not publish `.deb`, macOS archives or other endpoint binaries.
GitHub's source archives and this repository are the release artifacts.

## Upgrade

Back up private runtime configuration under `~/.faryo/`, then update the source
checkout and the isolated project environment:

```bash
git fetch origin --tags
git switch main
git pull --ff-only origin main
conda activate faryo
python -m pip install -r apps/gateway/requirements.txt
scripts/check-source.sh
```

Restart Owner and Gateway using the existing deployment scripts:

```bash
./apps/owner/scripts/start-web-owner.sh
systemctl --user restart faryo-gateway.service
```

Verify both loopback health endpoints and refresh existing browser tabs once so
the versioned browser assets reload.

## Security notes

- Keep Owner and Gateway loopback-only and protect the complete public hostname
  with an exact-identity access layer plus the independent Faryo login.
- Existing Cloudflare session lifetime and MFA choices are not changed by this
  release.
- The new private control audit is created beside other Gateway state, not in
  the repository. It is best-effort and cannot block a control response.
- `Sign out this device` and `Revoke signed-in devices` are distinct. Revocation
  invalidates inner Faryo cookies but does not stop Codex or close tmux.

## Compatibility changes

- The maintained fork is Codex-only. Inherited Claude launch paths, macOS
  launchd support and unvalidated binary package builders are not supported.
- The former `Confirm` control is now `Enter Choose`; the Owner compatibility
  endpoint remains `/api/approve`, but its semantics are an exact Enter key.
- Raw is complete terminal evidence; Chat is the rendered structured reading
  surface. They intentionally no longer share a capture cache.

## Rollback

Stop the two Faryo services, check out the previous known-good tag or commit,
reinstall that revision's declared dependencies, and start the services again.
Private `~/.faryo/` configuration, Codex rollout history and tmux sessions are
not stored in Git and should not be deleted during a source rollback.
