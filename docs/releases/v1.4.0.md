# Faryo 1.4.0

Faryo 1.4.0 modernizes the Gateway HTTP stack, splits the largest Owner/Gateway
responsibilities into testable modules, raises the conversation attachment
budget to 35, and adopts a tightly scoped local Preact card renderer.

## Highlights

- Gateway production now runs one Starlette/Uvicorn ASGI implementation. The
  former `http.server` Gateway, migration switch and duplicated route behavior
  are removed.
- The ASGI composition root delegates authentication, reads, Owner proxy/SSE,
  control/audit, Codex start/resume, bridge packages and MCP to separate route
  modules. Security, config, Owner transport, workbench aggregation, audit and
  bridge persistence each have one shared implementation.
- Owner now has independent modules for attachment storage, local path policy,
  tmux primitives, reliable-delivery storage/service, Codex history/App Server,
  browser HTTP primitives, workspace Changes and redacted diagnostics.
- The Owner browser composition root delegates API, attachments, history,
  capture and composer delivery to native ES modules. Markdown/TeX, transcript
  selection and Live tmux remain on the stable framework-free path.
- The composer accepts up to 35 pending attachments, processes at most four in
  parallel, keeps previews horizontally bounded, and retains the 25 MiB
  server-side limit for each uploaded file.
- The question-navigation rail is translucent while scrolling and becomes
  opaque only during pointer/touch/keyboard interaction, so it no longer hides
  as much conversation text.
- A local Preact 10.29.8 bundle now owns only file-package, launcher,
  active-session and history-session keyed lists. It removes hand-written card
  replacement and dynamic card `innerHTML`; Owner and rich transcript rendering
  do not move into a framework.
- Gateway service restart now closes active Owner streams before Uvicorn waits
  for request tasks. A response-owned socket shutdown unblocks an idle SSE
  `readline`, eliminating the former graceful-timeout forced cancellation.

## Dependency decisions

- Added Gateway runtime: Starlette 1.6.0 and Uvicorn 0.52.4, with exact base-only
  AnyIO, Click, h11 and idna pins. No standard/full extras, uvloop, watchfiles,
  WebSocket runtime or multipart parser is installed.
- Updated the exact bcrypt runtime pin to 5.0.0.
- Added development-only ESLint 10.8.1 and expanded Ruff 0.16.3 to the selected
  Bugbear checks used by canonical CI.
- Added Preact 10.29.8 as an exact build dependency. The committed local bundle
  is 17,753 bytes raw / 7,211 bytes gzip level 9, has no production transitive
  dependency, and ships a generated version/hash/size/MIT notice.
- Preact adoption is based on tested DOM-state and safe-text improvements, not a
  false total-source reduction claim. The complete measurement and removal path
  are in `docs/preact-pilot-evaluation.md`.
- A possible single-binary Go Gateway remains design-only. v1.4 records its
  protocol and ownership boundary without adding a second backend or Go
  toolchain.

## Security and reliability

- Gateway retains signed host-only Secure/HttpOnly/SameSite-Strict cookies,
  epoch revocation, CSRF on browser writes, trusted-proxy login limiting,
  nonce/self-only CSP, HSTS, `nosniff`, frame denial and route authorization.
- The maintained trusted-device default for the inner Faryo login is 30 days
  (`720` hours); deployments may choose any shorter value from 1 through 720.
  This remains independent from the outer identity-aware proxy session.
- Owner tokens and identity/scope headers remain server-side. Forwarded browser
  headers cannot replace them.
- Control audit remains body-free and uses pseudonymous targets. Tests and
  documentation contain no deployment identity, domain, token, cookie, private
  path, session title or conversation content.
- Reliable sends retain per-session serialization, stable message identity,
  restart idempotency, success-only draft clearing and explicit ambiguous
  failure without blind re-paste.
- Active SSE streams are registered, released idempotently and covered by a
  real silent-long-connection shutdown test.

## Upgrade

```bash
git fetch origin --tags
git switch main
git pull --ff-only origin main
conda activate faryo
python -m pip install -r apps/gateway/requirements.txt
python -m pip install -r requirements-dev.txt
npm ci --ignore-scripts
scripts/check-source.sh
./apps/owner/scripts/start-web-owner.sh
systemctl --user restart faryo-gateway.service
```

Refresh existing browser tabs once so the versioned Gateway scripts load. The
release does not migrate Codex rollout/SQLite data, tmux sessions, delivery
receipts, inbox files, audit data or private authentication configuration.

## Verification

- Canonical source gate: 126 Owner and 111 Gateway Python tests, Ruff, ESLint,
  Prettier, reproducible bundles, Node browser-module suites and npm audit.
- Explicit ASGI route contracts cover login/cookies/CSRF/CSP, reads/writes,
  Owner headers, normal streaming and SSE, uploads, MCP, audit and fallbacks.
- A real silent SSE fixture requires shutdown before its one-second gate.
- Isolated and deployed Gateway browser matrices pass at 1440x900 and 390x844,
  including three 10-record history pages, search/filter, directory selection,
  security/attention controls, keyed DOM/focus retention, safe card text and no
  horizontal page overflow.
- Owner matrices retain Markdown/KaTeX/Shiki, complete/lazy history,
  Chat/Raw isolation, 35-attachment scrolling, reliable send/retry, Live tmux,
  clipboard image paste, Changes, PWA/fullscreen and copy fidelity.
- Production services remain loopback-only, the unauthenticated public entry
  remains behind the external identity challenge, and every agent pane keeps
  its existing tmux geometry.

## Rollback

Check out the annotated `v1.3.0` source tag, install that revision's Python and
Node dependencies, and restart Owner/Gateway. No private-state downgrade or
tmux/Codex migration is required. The release is source-only and contains no
custom binary assets.
